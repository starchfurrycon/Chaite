# 拆特

[GitHub 源码](https://github.com/starchfurrycon/Chaite) · [验证记录](VERIFICATION.md)

“拆特”是面向 Windows Steam 原版 Terraria 的实验性 Boss 战斗接管器。当前唯一白名单版本是 **1.4.5.8**；它不是 tModLoader 模组，也不处理入侵、月亮或其他事件。生产接管白名单已经收拢为两个 Boss：猪鲨公爵（NPC type 370）与光之女皇（NPC type 636，昼夜形态都由原生阶段判定）。

工具通过可恢复的 IL 注入，在本地玩家更新入口、原版输入复制后、快捷栏处理后、`HorizontalMovement` 前及 Boss 掉落结算处加入五个入口。每帧只规划一次；后续三个玩家入口依次回放输入、恢复选槽／瞄准及复核已评分的可选机动边沿，不会重新扫描威胁或重新规划。战斗热路径完全离线，不截图、不联网、不运行大模型，不直接读写 .plr、.wld 或地图文件；游戏内的战斗与物品消耗仍由原版正常执行。

> 当前仍是实验性 alpha，不是成熟自动通关版本。旧版本的全 Boss 代码、批次和失败证据只保留作离线研究／回归，**不代表生产运行时会接管这些 Boss**，也不能据此宣称无伤或高胜率。猪鲨和光女的真实多种子验收仍需单独完成；请只用备份角色和世界试验。

当前开发源码仍保留[逐武器／弹药适配](docs/weapon-profile-policy.md)与各 Boss 原生阶段策略，供猪鲨／光女路线和离线回归使用。主弹道目录目前有 **885 个逐武器／弹药精确组合**；未列入生产目录或专用路线的复杂武器仍会明确拒绝，不把“有投射物”冒充为已适配。目录中其余 Boss 的画像不代表生产白名单已经扩大。

v0.5 的史莱姆王补测已扩展到普通／专家／大师各 4 个不同种子，全部零死亡通过；其余 Boss 必须分别补齐，不能用这 12 场替代。该结果仍未达到每格至少 40 个独立种子的统计门槛。

本轮源码已接入[普通跳／云跳状态模型](docs/native-jump-research.md)与[克眼原生阶段跑道策略](docs/boss-eye-native-policy.md)。六种固定原生跳跃轨迹、1080 帧配对通过；另完成十场逐项战斗对照，大师克眼样例由失败恢复为通关，但专家克眼变慢且受击增多，仍需优化。`tools/test-native-motion.ps1` 默认只展示计划，明确加 `-Run` 才会通过既有隔离机制启动测试副本，不运行正式游戏存档。

当前未发布的 v0.7 迭代新增[受限 Demon 飞行模型](docs/native-flight-policy.md)和[史莱姆皇后低空跑道策略](docs/boss-queen-native-policy.md)，277 项离线回归通过。八组、共 4800 帧原生竖直飞行轨迹已完成局部配对及独立自递推检查，位置最大误差为 0，速度最大误差约 4.77×10⁻⁷ 像素／帧。同一冻结构建的十病例为 6 胜 4 败：史后未击杀即脱战，毁灭者、双子和 Prime 死亡，且双子相对 v0.6 发生退化；这些失败正在下一轮修正，不能把本版当作通关版。

## 操作与启动门槛

- F8：尝试激活。
- F9：任何接管状态下立即清空自动输入、恢复武器并归还操作权。
- 激活只接受两条生产入口：快捷栏从左到右第一个当前可用的松露虫钓鱼（猪鲨）或七彩草蛉（光女），或者已经存在的猪鲨／光女战斗。已有 Boss 优先于召唤物；若 F8 时玩家正骑乘或挂钩，会保持原版输入并等待最多 5 秒，再重新读取状态做完整预检。任何其他 Boss、混合 Boss、自然排程或其他召唤物都会在不消耗物品、不发出控制输入的情况下拒绝，并播放 `boss_too_hard_for_me.wav`。真正接管后以观测到的当前原生阶段为准，先进入恢复态，再尝试收敛回对应稳定闭环；原生阶段缺失／未知或恢复无法推进时会中性归还操作。
- 接管前低频扫描玩家附近的碰撞地形，并分别读取奔跑、翅膀/火箭、活动坐骑、原版实际选中的坐骑、冲刺、钩爪、重力和羽落状态。最低配置表示对应 Boss 的机动能力门槛，而不是一套指定配装；身份目录只用于证明某种手段的真实参数。徒步、坐骑或其他手段只有在其独立逐 tick 控制路线确实达到门槛时，才可满足准入或产生按键。
- 七彩草蛉仍要求地表神圣环境、未启用小动物保护，并在释放后立即进入光女开战链；白天会直接按致命昼光女门槛预检，夜间则额外要求有足够剩余时间，避免刚开战就跨入白天。松露虫仍要求海边海水与钓竿。这里的门槛是安全准入，不是无伤或必胜保证。
- 猪鲨／光女仍会从上述目录中选择已经通过原生身份、弹道和资源证书的输出路线；其余武器画像只作离线研究。完整清单与复杂武器的拒绝原因见[武器适配策略](docs/weapon-profile-policy.md)。一律以原版实际选中的弹药、最终弹幕和实时资源为准；战斗中身份变成未知组合会停火并提示，避险仍继续，F9 可归还操作。
- `AutoSwitchWeapon=false` 时，启动前需手持上述可用武器；召唤临时换槽后回到这把武器，不自动按输出排名换枪。自动选枪时按直伤及完整连发周期比较，并在延迟换枪的过渡帧停火，避免使用旧枪的瞄准方案。
- 等待猪鲨／光女出现或已经发出召唤后，使用独立的低成本生存闭环清除近身敌怪，不把普通事件误当作成功条件。

## 特殊召唤

生产版只启用前两条专用动作链；表格后列出的其他动作链是旧版离线研究代码，不会在当前生产运行时触发：

| 召唤物 | 必要条件 | 自动动作 |
|---|---|---|
| 松露虫 | 海洋、附近有海水、快捷栏另有钓竿 | 面向水体抛竿，确认自己的浮标后收线；原版在收回松露虫浮标时生成猪鲨并消耗松露虫 |
| 七彩草蛉 | 地表神圣、未启用小动物保护；夜间还需有足够剩余时间 | 释放后锁定 NPC 661，立即切换快捷栏武器并击杀；白天按致命昼光女门槛预检 |
| 丛林蜥蜴电池／向导巫毒娃娃等旧入口 | 仅离线研究 | 生产运行时一律拒绝，不会消费物品 |

其他召唤物仍可被离线选择器识别，便于回归旧策略；生产运行时不会把它们当作可接管入口，而是播放“这个波斯可是超囊的对我来说”。

松露虫与草蛉释放会等待旧物品动画完成、选槽真正生效，再发出使用脉冲；按键发出不算召唤成功，以消耗或 Boss 出现为证。其他 Boss 的召唤流程不会进入生产接管。

## 战斗规划

当前产品目标只针对猪鲨公爵，以及光之女皇的夜间和白天变种：在声明的最低机动、场地和输出条件下形成机械化闭环。其他 Boss 不属于生产目标，接管请求直接拒绝；这只是开发目标，当前没有逐 Boss 大样本证据证明“接近 100%”结论。

逐 Boss 验收要求猪鲨、光女昼间和光女夜间分别按难度、场地、机动路线、武器／弹药配置统计，不以其他变种的胜利抵消失败。现有 `tools/evaluate-boss-readiness.ps1` 仍使用统一门禁：预先固定目标及独立抽样种子清单，每格至少 40 个不同种子，且双侧 95% Wilson 区间下界不低于 90%；这不能把离线阶段回归转换成“接近 100%”证明。死亡、超时、重复种子和缺证据不能补成胜利。

最低机动配置先按 Boss／难度所需的速度、可控垂直机动、爆发位移、制动与回到稳定循环等**能力门槛**表达，再由当前角色选择一条完整的实现路线。玩家自身运动已达标就使用徒步／翅膀路线；某个具体坐骑独立达标时可以改用该坐骑，不必再满足翅膀门槛；某些 Boss 的能力门槛也可以包含必需冲刺。物品身份不是目标，只是其原生参数和控制语义的证书。各路线仍须单独完成逐 tick、场地碰撞、威胁、制动和返回闭环，不能把背包中不能同时工作的能力拼成并集，也不能用未建模的“任意飞行坐骑／任意冲刺”冒充达标。开始接管后会锁定已选运动模型；高于门槛但闲置的装备不会静默改写稳定打法。

固定低配路线与可选高配救险分层验收，额外能力不能静默改写低配闭环。羽落状态即使不按键也会改变自然下落；已建模分支中，中性为三分之一重力、按上为十分之一重力、按下才绕过羽落恢复普通重力。只有精确羽落药水身份才授权主动按上，来源未知或语义冲突时不会猜测发键。

当前专家／大师猪鲨的能力门槛包含“已认证的冲刺—制动—返回闭环”；现阶段唯一完成该证书的实现来源是物品 `3097` 的克苏鲁之盾，因此其他未建模冲刺暂不能通过，而不是把克盾这件配装本身写成永久要求。规划器只在原生冲锋阶段且完整起步、衰减、制动、威胁规避和返回路线成立时发出冲刺；闭环不成立时不会为了凑门槛硬按。普通难度不要求这一爆发机动维度。

原版 1.4.5.8 的 `MountID 0..65` 已全部进入身份目录，其中 27 种是矿车；活动坐骑身份和 `QuickMount_GetItemToUse()` 实际选中的物品／坐骑对会分别发布。目录记录只说明“它是哪一种”，不说明“拆特会驾驶它”。女巫扫帚 `item 4444 / mount 23 / buff 230` 目前已有受限干燥开阔路径的纯运动与完整救援轨迹检查，但尚未接入生产 Boss 控制器；因此当前正式规划遇到任何活动坐骑都会输出全中性并归还操作，也绝不会因为背包里有坐骑就自行按下坐骑键。完成某一具体坐骑的生产闭环后，才会把它列入对应 Boss 的正式下限路线。

普通 Grappling Hook `item 84 / projectile 13` 也已具备精确只读身份、纯运动、路线证书和控制器回归，但控制器尚未被任何生产 Boss 规划路径调用；当前遇到活动抓钩仍会全中性归还操作，不会自动发射或猜测解钩。读取／验证代码存在不等于生产接线完成。

用 `-Summary <项目内绝对 summary.json 路径> -DescribeProfiles` 可只读查看构建及配置身份；正式计算另传 `-Targets <预声明目标 JSON>`。默认只输出 JSON，未达标退出码为 2；此工具补充统计，不代替原生证据和文件清单审计。开发中的同种子回归不得事后改称未见独立验收样本。

源码仍保留每个原版 Boss 的独立策略及阶段标签，但它们只用于离线研究与回归：

- 肉前：史莱姆王、克苏鲁之眼、世界吞噬怪、克苏鲁之脑、蜂王、骷髅王、独眼巨鹿、血肉墙。
- 肉后：史莱姆皇后、双子魔眼、毁灭者、机械骷髅王、世纪之花、石巨人、猪鲨公爵、光之女皇、拜月教邪教徒、月亮领主。
- 机械混战、天顶世界机械美杜莎，以及任意不同 Boss 家族同时存在时，生产边界会在接管前拒绝，而不是尝试复合控制。

上层模式为 EstablishPattern → StablePattern。即将碰撞时短暂进入 EmergencyEvade，脱离后经 RecoverToPattern 回到原闭环。方向有滞回，场地边缘按制动距离提前回转；飞行资源不足时进入降落、补充资源与重新起飞的恢复过程。克盾冲刺和重力药水翻转只有在精确身份、输入边沿、完整威胁轨迹与返回闭环都成立时才作为评分候选；未接入生产闭环的活动坐骑或活动抓钩会立即中性归还操作。

v0.3 修复原版延迟换槽被旧槽位回放取消的问题；当时曾用原版“松开跳跃→跳跃”脉冲解钩。当前生产版已用上述 fail-closed 边界取代该通用解钩逻辑，只有将来接入完整普通抓钩路线证书后才会重新授权脉冲。跑鞋按基础速度与疾跑速度分段预测，考虑空中加速限制、制动和减速；倒置重力时正确转换瞄准坐标。

v0.4 补齐落地后的松跳/重按、平台单向通行，以及迷你鲨/发条式突击步枪的原生只读选弹和子更新弹速换算。风筝模式会保持交战距离；毁灭者分开选择射击体节与头部避让参考、优先可见目标/近身探测怪，并在脚下有已观测落脚面时争取高度。目标视线缓存最多保留 12 帧，任一端移动超过 64 像素失效；每帧最多 3 条探索射线，加开火前 1 条原版即时射线。

平台不再按横向空旷宽度推断支撑：新落点只采用实际连续、净空足够的平顶表面，离开边缘会预测下坠，并检查移动中真正穿过落点高度时的横坐标。飞行资源不足时提前回接近期验证过的落脚区，紧急避障仍可覆盖这条回接路线。支撑扫描垂直最多 70 格、连续行左右各 96 格，沿用局部缓存；落地、重力或站立高度变化会提前刷新。斜坡、半砖不作为已验证的新平顶落点，不承诺任意地形的全程可达性。

飞行恢复只用于实际装备有有限飞行资源的角色；普通地面跳跃不会触发回接。装备判定不单看当前剩余条或原版火箭计时的默认上限，因此既不把无翼角色当成耗尽，也不漏掉真正耗尽的翅膀/火箭靴。

通常安全路线只评估 1 个候选，危险或恢复时才展开有限候选。不同候选共享弹幕预测缓存，累计风险剪枝只跳过已不可能获胜的候选；不会减少预测时长或丢掉多 Boss 来换速度。攻击目标与绕行中心分开，最后对实际射击目标执行原版视线检查。坐骑和钩爪读取原版实际会选中的物品，不把不同坐骑、不同抓钩或库存中的闲置装备拼成不存在的运动能力。

“有策略”不代表“可独立发起”：除猪鲨和光女外的策略只存在于离线目录，永远不会获得生产控制权。策略覆盖也不等于已经逐 Boss 实战验证。

## 构建与离线验证

要求 Visual Studio 2022（.NET 桌面开发）和 .NET Framework 4.8：

    ./tools/build.ps1 -Configuration Release -Package

默认新包输出位于 artifacts/Chaite-v0.7.0-alpha。打包先执行 x86 回归、离线证据门禁、逐 Boss 统计工具回归，以及后台 UI 布局检查；不删除已有包，同名目录存在时需指定新的 `-PackageVersion`。依赖本机白名单 Terraria 的 API／注入点、抓钩和坐骑元数据审计需在正式发布前另行运行，打包命令本身不会加载或执行 Terraria。已生成的 v0.1 至 v0.6 alpha 包留作回退；修改默认版本号不代表新包已经通过原生验收。

在拥有白名单游戏文件的开发机上，可分别运行 `./tools/audit-native-mount-catalog.ps1`、`./tools/audit-native-mount-motion-matrix.ps1` 和 `./tools/audit-native-dash-sources.ps1`。这些命令锁定游戏与 Mono.Cecil 哈希，只读取 PE/IL 元数据和目录源码，不加载或执行 Terraria；它们分别核对坐骑身份映射、39 种非矿车坐骑的原生运动矩阵，以及原版冲刺来源与状态机。它们是正式发布前的本机只读审计，不属于无游戏文件的 CI 或可移植打包门禁。

运行 Chaite.Manager.exe 可查看白名单状态、安装或恢复。新版界面采用深蓝/琥珀色分区、固定底部操作区和醒目的 F9 提示；状态哈希检查在后台防抖执行，避免输入路径时卡住界面。安装、恢复均有默认取消的确认。安装器：

1. 要求 Terraria 已退出，绝不会代为结束进程。
2. 同时校验文件版本和完整 SHA-256；未知更新一律拒绝。
3. 在 Terraria/Chaite 保存哈希锁定的原版备份和 XML 清单。
4. 先写临时程序集并验证注入点，再原子替换。
5. 恢复时只有当前文件仍与清单中的 patched hash 一致才覆盖，避免误抹 Steam 更新或其他修改。
6. 每次成功安装都会更新 `Audio/README.txt`；已有 `config.json` 和用户 WAV 始终保留，不覆盖也不删除。

命令行：

    Chaite.Patcher.exe status
    Chaite.Patcher.exe install
    Chaite.Patcher.exe restore

## 当前支持边界

- 仅支持白名单中的 Windows Steam Terraria 1.4.5.8 x86；游戏更新后必须重新验证字段、Boss AI 和注入点。
- 自动选择武器只看快捷栏，不整理背包、不改装备；特殊召唤只进行原版流程必需的选槽、输入与单个巫毒娃娃拆堆。
- 单机死亡通常会使普通 Boss 立即消失，因此会按“死亡后无法继续”终止；多人状态下 Boss 仍在则复活后继续。
- 周边地形扫描每 20 tick 或玩家明显移动后更新，范围只覆盖策略需要的局部净空与钩爪锚点，不进行全世界扫描。
- 普通跳、云瓶与一个固定 Demon Wings／Lightning Boots 子集已有原生逐 tick 合同，但其他二段跳、翅膀、火箭靴批次、坐骑、冲刺和组合装备仍需逐来源扩展；不能把“读到机动饰品”当成已充分利用其能力，也不能依据单场胜负调整距离常数。
- 局部净空是近似边界，不是整片场地的精确可达性证明；钩爪使用保守射程，复杂斜坡、平台和极端装备组合仍需实测。
- 普通弹幕预测包含线性运动、扫掠碰撞和寿命；月亮领主死亡射线与光女日舞已加入专用旋转、预热、宽度与连续扫掠模型。发射源未来运动仍近似为线性，不保证避开所有攻击。
- 预检尚未完整估算生命、护甲、法力/弹药总量与实际武器循环 DPS；除女巫扫帚的受限纯模型外，坐骑还没有可用于生产 Boss 战的完整运动／场地／疲劳闭环。“通过基础开战检查”不是胜率保证，不能据此自动消耗珍贵召唤物反复试错。
- 原版手柄锁定/辅助瞄准可能在回放后改写瞄准；当前实测为键鼠输入路径，手柄模式尚未验收。
- 已在工作区独立副本中运行原版无渲染战斗更新，经典克眼自动召唤、输出、击破与结束链通过，零死亡但有受伤。没有安装到正式游戏目录或读取用户角色/世界。私有桌面完整图形客户端受 XNA 显卡初始化限制，未改用用户桌面；无渲染测试不等于完整客户端、近战判定或逐 Boss 验收。

## 后台原版引擎测试（开发者）

需要本机拥有白名单原版及 XNA 运行库。每次使用新的目录：

```powershell
.\tools\prepare-game-probe.ps1 -RunName game-probe-local01 -Headless
.\tools\start-isolated-test.ps1 -TargetExe "$PWD\artifacts\game-probe-local01\Terraria.exe" -OutputDirectory "$PWD\artifacts\game-probe-local01-desktop"
```

启动器核对所有运行文件哈希，强制工作区 Save 路径、禁用 Steam/social，不发送系统按键、不切换桌面。只允许单次运行，不复用有日志/存档的目录；测试角色及场地仅在内存中创建，存盘入口被测试副本禁止。退出码 0 需要完整战胜断言通过，拒绝激活、超时、原版异常或接管错误均非成功。光照、成就使用隔离的原版数据初始化；文字弹出与碎块呈现被省略。测试工具和副本不是可分发的游戏版本，GitHub 不包含任何 Terraria 文件或音频。
