# 拆特

[GitHub 源码](https://github.com/starchfurrycon/Chaite) · [验证记录](VERIFICATION.md)

“拆特”是面向 Windows Steam 原版 Terraria 的实验性 Boss 战斗接管器。当前唯一白名单版本是 **1.4.5.8**；它不是 tModLoader 模组，也不处理入侵、月亮或其他事件。

工具通过可恢复的 IL 注入，在本地玩家更新、原版输入复制后、快捷栏处理后及 Boss 掉落结算处加入四个入口。每帧只规划一次，后两个玩家入口只回放结果，避免原版输入覆盖接管。战斗热路径完全离线，不截图、不联网、不运行大模型，不直接读写 .plr、.wld 或地图文件；游戏内的战斗与物品消耗仍由原版正常执行。

> 当前仍是实验性 alpha，不是成熟自动通关版本。新源码回归中，史莱姆王三难度及普通双子样例通关，但大师克眼、普通史后／毁灭者／机械骷髅王仍失败；**没有达到每个 Boss 独立高成功率的目标**。不能用混合总胜率掩盖个别 Boss 打不过。逐项结果见[验证记录](VERIFICATION.md)，请只用备份角色和世界试验。

当前开发源码新增了[逐武器／弹药适配](docs/weapon-profile-policy.md)与[史莱姆王原生阶段策略](docs/boss-king-native-policy.md)。旧 v0.4 的 18 场证据和回退包单独保留，不合并统计。**现在仅有 4 个明确的武器／弹药组合，尚未完成全武器适配。**

v0.5 的史莱姆王补测已扩展到普通／专家／大师各 4 个不同种子，全部零死亡通过；其余 Boss 必须分别补齐，不能用这 12 场替代。该结果仍未达到每格至少 40 个独立种子的统计门槛。

## 操作与启动门槛

- F8：尝试激活。
- F9：任何接管状态下立即清空自动输入、恢复武器并归还操作权。
- 激活只接受两类状态：快捷栏从左到右第一个“此刻确实可用”的 Boss 召唤物；原版内部已经排定的克苏鲁之眼、机械 Boss 或月亮领主。仅有 Boss 在场不能启动，同一家族 Boss 已在场时不会重复使用该家族召唤物。
- 接管前低频扫描玩家附近的碰撞地形，并读取奔跑速度、翅膀/火箭资源、坐骑、冲刺、钩爪、重力和羽落能力。达不到对应策略的最低净空或机动性时会拒绝启动。
- 夜间眼球、机械召唤及自然排程、普通世界草蛉入口保留至少 7200 世界时间单位再接受启动。这是额外安全策略，**不是**原版召唤限制、预计击杀时间或加速时间下的两分钟保证。天顶世界地表草蛉会引出未验证的暴怒光女，暂拒绝自动释放。
- 当前只接受迷你鲨、发条式突击步枪分别搭配火枪子弹或水晶子弹；以原版实际选中的弹药为准。其他组合明确拒绝开战，不把“有投射物”当作已适配。战斗中弹药变成未知组合会停火并提示，避险仍继续，F9 可归还操作。
- `AutoSwitchWeapon=false` 时，启动前需手持上述可用武器；召唤临时换槽后回到这把武器，不自动按输出排名换枪。自动选枪时按直伤及完整连发周期比较，并在延迟换枪的过渡帧停火，避免使用旧枪的瞄准方案。
- 等待自然 Boss 或已经发出召唤后，使用独立的低成本生存闭环清除近身敌怪，不把普通事件误当作成功条件。

## 特殊召唤

普通召唤物仍交给原版物品使用代码处理。以下物品使用专用动作链：

| 召唤物 | 必要条件 | 自动动作 |
|---|---|---|
| 松露虫 | 海洋、附近有海水、快捷栏另有钓竿 | 面向水体抛竿，确认自己的浮标后收线；原版在收回松露虫浮标时生成猪鲨并消耗松露虫 |
| 七彩草蛉 | 夜间地表神圣、未启用小动物保护 | 释放后锁定 NPC 661，立即切换快捷栏武器并击杀 |
| 丛林蜥蜴电池 | 祭坛在交互距离 | 瞄准祭坛并执行右键交互 |
| 向导巫毒娃娃 | 地狱、向导存活；正向重力，静止站在开阔岩浆池旁；鼠标上没有物品 | 验证短投掷弧后，同步调用原版丢弃 1 个；同帧恢复堆叠余量与收藏状态，失败则完整恢复 |

其他可识别召唤物包括可疑眼球、蠕虫诱饵、史莱姆王冠、憎恶之蜂、血腥脊椎、三种机械召唤物、明胶水晶、鹿华、天界符和奥库瑞姆剃刀。基于 1.4.5.8 原版条件，并增加上述明确标出的安全门槛；对通常只能在肉后取得、但原版允许从其他世界带入后提前使用的物品，不额外捏造进度限制。

普通物品、祭坛和草蛉释放会等待旧物品动画完成、选槽真正生效，再发出使用脉冲；按键发出不算召唤成功，以消耗或 Boss 出现为证。血肉墙不自动寻找路线或把娃娃“瞄准发射”到远处岩浆，投掷落点不确定时拒绝操作。

## 战斗规划

逐 Boss 验收要求每个声明的 Boss×难度×变种×装备／场地／武器弹药配置分别通过，不以其他 Boss 的胜利抵消某一项失败。新增的 `tools/evaluate-boss-readiness.ps1` 要求预先固定完整目标及独立抽样种子清单，每格至少 40 个不同种子，且双侧 95% Wilson 区间下界不低于 90%；死亡、超时、重复种子和缺证据不能补成胜利。未测试的项目显示未验证。这是有条件的逐格统计门槛，不是必胜或所有组合同时具备 95% 置信度的证明。

用 `-Summary <项目内绝对 summary.json 路径> -DescribeProfiles` 可只读查看构建及配置身份；正式计算另传 `-Targets <预声明目标 JSON>`。默认只输出 JSON，未达标退出码为 2；此工具补充统计，不代替原生证据和文件清单审计。开发中的同种子回归不得事后改称未见独立验收样本。

每个原版 Boss 都有独立策略及阶段标签：

- 肉前：史莱姆王、克苏鲁之眼、世界吞噬怪、克苏鲁之脑、蜂王、骷髅王、独眼巨鹿、血肉墙。
- 肉后：史莱姆皇后、双子魔眼、毁灭者、机械骷髅王、世纪之花、石巨人、猪鲨公爵、光之女皇、拜月教邪教徒、月亮领主。
- 机械混战、天顶世界机械美杜莎，以及任意不同 Boss 家族同时存在时分别使用专用或复合策略；不会打掉其中一个就提前结束。

上层模式为 EstablishPattern → StablePattern。即将碰撞时短暂进入 EmergencyEvade，脱离后经 RecoverToPattern 回到原闭环。方向有滞回，场地边缘按制动距离提前回转；飞行资源不足时进入降落、补充资源与重新起飞的恢复过程。钩爪、坐骑与重力反转有动作冷却，锚点需在射程内且不受已知威胁覆盖。

v0.3 修复原版延迟换槽被旧槽位回放取消的问题；钩爪挂住后使用原版“松开跳跃→跳跃”脉冲解钩。跑鞋按基础速度与疾跑速度分段预测，考虑空中加速限制、制动和减速；倒置重力时正确转换瞄准坐标。

v0.4 补齐落地后的松跳/重按、平台单向通行，以及迷你鲨/发条式突击步枪的原生只读选弹和子更新弹速换算。风筝模式会保持交战距离；毁灭者分开选择射击体节与头部避让参考、优先可见目标/近身探测怪，并在脚下有已观测落脚面时争取高度。目标视线缓存最多保留 12 帧，任一端移动超过 64 像素失效；每帧最多 3 条探索射线，加开火前 1 条原版即时射线。

平台不再按横向空旷宽度推断支撑：新落点只采用实际连续、净空足够的平顶表面，离开边缘会预测下坠，并检查移动中真正穿过落点高度时的横坐标。飞行资源不足时提前回接近期验证过的落脚区，紧急避障仍可覆盖这条回接路线。支撑扫描垂直最多 70 格、连续行左右各 96 格，沿用局部缓存；落地、重力或站立高度变化会提前刷新。斜坡、半砖不作为已验证的新平顶落点，不承诺任意地形的全程可达性。

飞行恢复只用于实际装备有有限飞行资源的角色；普通地面跳跃不会触发回接。装备判定不单看当前剩余条或原版火箭计时的默认上限，因此既不把无翼角色当成耗尽，也不漏掉真正耗尽的翅膀/火箭靴。

通常安全路线只评估 1 个候选，危险或恢复时才展开 9 候选。不同候选共享弹幕预测缓存，累计风险剪枝只跳过已不可能获胜的候选；不会减少预测时长或丢掉多 Boss 来换速度。攻击目标与绕行中心分开，最后对实际射击目标执行原版视线检查。坐骑和钩爪读取原版实际会选中的物品，不把不同坐骑的能力拼在一起。

“有策略”不代表“可独立发起”：骷髅王、世纪之花、邪教徒等没有当前支持的快捷栏召唤入口，只会在已合法启动的会话中参与战斗。策略覆盖也不等于已经逐 Boss 实战验证。

## 构建与离线验证

要求 Visual Studio 2022（.NET 桌面开发）和 .NET Framework 4.8：

    ./tools/build.ps1 -Configuration Release -Package

输出位于 artifacts/Chaite-v0.4.0-alpha。打包先执行 x86 回归测试及后台 UI 布局检查；不删除已有包，同名目录存在时需指定新的 `-PackageVersion`。旧 v0.1.0/v0.2.0/v0.3.0-alpha 留作回退。

运行 Chaite.Manager.exe 可查看白名单状态、安装或恢复。新版界面采用深蓝/琥珀色分区、固定底部操作区和醒目的 F9 提示；状态哈希检查在后台防抖执行，避免输入路径时卡住界面。安装、恢复均有默认取消的确认。安装器：

1. 要求 Terraria 已退出，绝不会代为结束进程。
2. 同时校验文件版本和完整 SHA-256；未知更新一律拒绝。
3. 在 Terraria/Chaite 保存哈希锁定的原版备份和 XML 清单。
4. 先写临时程序集并验证注入点，再原子替换。
5. 恢复时只有当前文件仍与清单中的 patched hash 一致才覆盖，避免误抹 Steam 更新或其他修改。

命令行：

    Chaite.Patcher.exe status
    Chaite.Patcher.exe install
    Chaite.Patcher.exe restore

## 当前支持边界

- 仅支持白名单中的 Windows Steam Terraria 1.4.5.8 x86；游戏更新后必须重新验证字段、Boss AI 和注入点。
- 自动选择武器只看快捷栏，不整理背包、不改装备；特殊召唤只进行原版流程必需的选槽、输入与单个巫毒娃娃拆堆。
- 单机死亡通常会使普通 Boss 立即消失，因此会按“死亡后无法继续”终止；多人状态下 Boss 仍在则复活后继续。
- 周边地形扫描每 20 tick 或玩家明显移动后更新，范围只覆盖策略需要的局部净空与钩爪锚点，不进行全世界扫描。
- 原版按住跳跃延长上升、云瓶等空中二段跳的剩余状态与释放/重按时序尚未完整建模；不能把“读到机动饰品”当成已充分利用其能力。下一步需要原生逐 tick 跳跃对照，而不是依据单场胜负调整距离常数。
- 局部净空是近似边界，不是整片场地的精确可达性证明；钩爪使用保守射程，复杂斜坡、平台和极端装备组合仍需实测。
- 普通弹幕预测包含线性运动、扫掠碰撞和寿命；月亮领主死亡射线与光女日舞已加入专用旋转、预热、宽度与连续扫掠模型。发射源未来运动仍近似为线性，不保证避开所有攻击。
- 预检尚未完整估算生命、护甲、法力/弹药总量与实际武器循环 DPS；有限飞行坐骑也没有完整的疲劳/续航模型。“通过基础开战检查”不是胜率保证，不能据此自动消耗珍贵召唤物反复试错。
- 原版手柄锁定/辅助瞄准可能在回放后改写瞄准；当前实测为键鼠输入路径，手柄模式尚未验收。
- 已在工作区独立副本中运行原版无渲染战斗更新，经典克眼自动召唤、输出、击破与结束链通过，零死亡但有受伤。没有安装到正式游戏目录或读取用户角色/世界。私有桌面完整图形客户端受 XNA 显卡初始化限制，未改用用户桌面；无渲染测试不等于完整客户端、近战判定或逐 Boss 验收。

## 后台原版引擎测试（开发者）

需要本机拥有白名单原版及 XNA 运行库。每次使用新的目录：

```powershell
.\tools\prepare-game-probe.ps1 -RunName game-probe-local01 -Headless
.\tools\start-isolated-test.ps1 -TargetExe "$PWD\artifacts\game-probe-local01\Terraria.exe" -OutputDirectory "$PWD\artifacts\game-probe-local01-desktop"
```

启动器核对所有运行文件哈希，强制工作区 Save 路径、禁用 Steam/social，不发送系统按键、不切换桌面。只允许单次运行，不复用有日志/存档的目录；测试角色及场地仅在内存中创建，存盘入口被测试副本禁止。退出码 0 需要完整战胜断言通过，拒绝激活、超时、原版异常或接管错误均非成功。光照、成就使用隔离的原版数据初始化；文字弹出与碎块呈现被省略。测试工具和副本不是可分发的游戏版本，GitHub 不包含任何 Terraria 文件或音频。
