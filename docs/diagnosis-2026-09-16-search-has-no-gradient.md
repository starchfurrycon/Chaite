# 诊断：搜索没有梯度可用（2026-09-16）

本轮训练（`empress-broom-nohit-v4`）产生了两代真实数据，加上一轮引擎内的边距标定，
结论不是"超参没调好"，而是**这个残差结构在当前脚本附近不存在可达的改进方向**。
下面每一条都有实测数字，没有推断。

## 1. 训练器里已有的东西（先纠正一个常见误判）

`tools/train-policy.ps1` **已经**实现了三项通常被建议补上的技术：

| 技术 | 位置 | 状态 |
|---|---|---|
| 镜像/对偶采样（±ε 成对） | `$script:pairG`，候选循环 `$c % 2` | 已有 |
| 秩加权更新（中心化秩） | `$utilities`，`u = r/(n-1)*2-1` | 已有 |
| 从零初始化（零权重 ≡ 脚本） | `$mean = New-Object double[] $WeightCount` | 已有 |

所以"补 rank shaping / 镜像采样"不是本轮的瓶颈。瓶颈在**参数化**。

## 2. 根因：argmax 尺度不变 + 零权重是一个精确平局

`LearnedPolicy.Adjust` 用四个头做离散覆盖：

```csharp
var hx = ArgMax(0, 3);                              // 0 = 不干预, 1 = −1, 2 = +1
if (hx == 1) horizontal = ClampStep(scriptedHorizontal - 1);
if (ArgMax(6, 2) == 1) jump = !scriptedJump;
```

`ArgMax` 用严格 `>`，平局归 index 0。零权重时 10 个 logit **全为 0**，于是全部归 0，
精确等于脚本。但这同时意味着：

- **任意非零扰动都会打破这个平局**——无论多小；
- **`ArgMax` 对整体尺度不变**，所以 σ=0.1 和 σ=0.001 产生的动作分布近乎相同，
  σ 和 σ 退火规则**在修复前是无效的**；
- 三类头（水平/垂直）在随机 logit 下 class 0 只有约 1/3 胜率 ⇒ **约 2/3 的 tick 被覆盖**。

这不是"随机控制器略微变差"，而是"随机控制器取代脚本"。

## 3. 实测证据链

### 3.1 世代 1：16 个候选里 15 个是灾难

| | ticks（6 种子 min/max） | dmgSum | hitsSum | fitness |
|---|---|---|---|---|
| parent（= 固定机器） | **1876 / 1876** | 139,442 | 6 | 0.08286 |
| c3 | **1873 / 1873** | 144,138 | 6 | 0.08685 |
| c2 | 782 / 782 | 36,311 | 6 | −0.00484 |
| c6 | 596 / 600 | 20,748 | 6 | −0.01807 |
| c11 | 338 / 619 | 19,002 | 6 | −0.01956 |

`-StopOnHit` 下 `deaths=0`、`hits=1`，回合**在第一次受击时结束**。所以
`ticks` 就是"存活到第一次受击的时间"，而 fitness 完全没用它。
c3 的 1873 ≈ parent 的 1876 说明 **c3 实际上是一个几乎空操作的扰动**，
它是 16 个里唯一没有毁掉脚本的，因此被选为"最佳"。

### 3.2 世代 2：更新把父代打坏

```
1,parent,...,0.08286        gen1 父代
1,3,...,0.08685,...hits=12  "胜出"候选 c3
2,parent,...,0.00837        gen2 重新评测更新后的权重
```

`hits=12` 本身暴露了另一个 bug（见 §4）。而 0.08286 → 0.00837 是**更新本身造成的退化**：
16 个候选里 15 个远差于父代，秩加权方向由这些坏样本主导，步长 `0.31826` 又比 σ 还大。

### 3.3 引擎内边距标定（零中心 σ=0.1 扰动，seed 1/2）

```
margin   seed1                    seed2
0        ticks= 625 dmg= 3701      ticks= 636 dmg= 4322
0.01     ticks= 621 dmg= 3687      ticks= 636 dmg= 4322
0.04     ticks= 627 dmg= 3915      ticks= 637 dmg= 4374
0.08     ticks= 611 dmg= 3932      ticks= 611 dmg= 3594
0.15     ticks= 610 dmg= 3923      ticks= 610 dmg= 3522
（另一份非零均值扰动在 margin 0.25 时逐位回到固定机器 1876）
```

**响应是阶跃而非渐变**：M 从 0 加到 0.15 结果几乎不动，然后在 0.15→0.25 之间跳到 1876。
原因是**胜负在最初约 600 tick 就锁定**——一旦策略在关键期覆盖了脚本，
之后再压住后续覆盖也救不回来。

### 3.4 margin 固定 0.25、扫 σ（零中心扰动，seed 1/2）

```
sigma 0.1   ticks= 661           ← M=0.25 对零中心扰动并未压住
sigma 0.15  ticks= 686/674
sigma 0.2   ticks= 727/727
sigma 0.3   ticks= 1213/1213     ← 最好，仍远低于 1876
sigma 0.45  ticks= 720/720
sigma 0.7   ticks= 727/727
```

**修复被验证**：σ 从"完全无效"变成真旋钮（661–1213 随 σ 变化）。
但**没有任何 σ 能回到 1876**。同一个 M 在不同权重向量上给出的覆盖率不同，
所以固定 M 无法统一控制覆盖率——这是该方案的固有局限。

## 4. 本轮修掉的三个训练器缺陷

1. **`Get-ResultFor` 吸收历史目录**（已修）。`-like "game-probe-rt-$RunTag-*"` 会匹配
   **同一 tag 的所有历史运行**。世代 1 的 6 种子批次记出 `hits=12`，因为 20 分钟前
   那次中止运行的 6 个目录还在盘上，12 行被一起平均。这次 12 行恰好位相同（确定性环境 +
   相同参数）所以 fitness 没受影响，但 `wins`/`noHit` 计数翻倍，而且**任何参数已变化的
   重启都会被静默混入**。现改为每个 seed 只取最新目录。
2. **接受判定缺失**（已修）。原代码无论测得是否更差都保留试探均值，并且"最佳候选 > 父代"
   判据在父代被自己替换后恒为真，σ 衰减规则因此**从未触发**。现改为回溯线搜索：
   因为环境对 (weights, seed) 确定性，父代与试探点的比较**没有采样噪声**，
   所以接受即为真实改进、拒绝即为真实退化。未被接受的步会回退并减半学习率。
3. **σ 衰减由接受判定驱动**（已修），下限从 0.02 降到 0.005（修复前该下限无意义）。

## 5. 结构性修复：class-0 边距

`LearnedPolicy` 新增 `DefaultActionMargin`（环境变量 `CHAITE_DEFAULT_ACTION_MARGIN`
覆盖，默认 1.0），在四个头的 class-0 logit 上加一个固定量。效果：

- 零权重**仍然精确等于脚本**（所有 logit 为 0，class 0 靠边距胜出）——已在引擎内验证；
- 覆盖条件变成 `logit[k] > logit[0] + M`，logits 随权重尺度线性增长而 M 固定，
  于是 **σ 恢复为有效旋钮**——已在引擎内验证（§3.4）；
- 策略从"取代脚本"变回"稀疏修正脚本"。

实测正负对照都成立：M=0 时分支确实执行（1887 ≠ 1876，两个种子都变），
M 足够大时逐位回到固定机器，零权重在任何 M 下都等于脚本。

## 6. 战略结论

**瓶颈不是优化器，而是"当前脚本附近不存在可达的改进方向"。**

实测约 30 个扰动（σ 0.1–0.7、M 0–2）中，**没有一个达到父代的 1876 ticks**。
脚本是一个局部最优，而随机扰动 794 维权重几乎必然破坏它在最初 600 tick 的关键决策。
继续用随机方向搜索只会得到"退化为空操作"或"退化为灾难"两种结果。

三条可能的出路，按预期性价比排序：

1. **降低有效维数**：只扰动一个头（例如只管 dash 或只管 jump）而不是全部 794 个参数。
   单个头的 head 层是 `3×16+3 = 51` 维（jump/dash 是 `2×16+2 = 34` 维），
   扰动落在脚本附近的概率高得多，且四类决策在脚本里是独立的。
2. **给残差加时间/相位门控**：既然胜负在最初约 600 tick 锁定，
   让策略只在特定脚本相位（例如某一种攻击的应对）内允许覆盖，
   而不是每个 tick 都有权覆盖全部四个决策。
3. **先人工改脚本**：脚本 46 种子只赢 2 次、0 次无伤，本身接近失效。
   把它改到更高基线，再让残差去磨最后一点。
   DSLE（arXiv:2608.09902，Dark Souls boss 基准，与本题设定同构）的经验支持这条：
   进化基线在教程 boss 上 43% 胜率，而 PPO/DQN 在同预算下 0.33%/0%。

**不建议**：深度 RL（DSLE 已实测失败）、全协方差 CMA-ES（794 维 + λ=16 不可行）、
高维 GP 代理模型、"重采样平均噪声"（环境对 (weights, seed) 完全确定，
重复跑同一 rollout 零新信息）。

## 7. 复现命令

```
# 构建（改动 LearnedPolicy 后必须重新构建）
pwsh -File tools/build.ps1

# 边距标定：固定策略 × 扫 margin
pwsh -File artifacts/_sweep-margin.ps1     # 粗扫（非零均值扰动）
pwsh -File artifacts/_sweep-margin2.ps1    # 细扫（零中心 σ=0.1）
pwsh -File artifacts/_sweep-sigma.ps1      # margin 固定 0.25、扫 σ

# 训练
pwsh -File tools/train-policy.ps1 -Mode train -Tag <tag> -Scenario empress-night `
    -Route empress-broom -PolicyRoute EmpressBroom -Population 16 `
    -SeedsPerCandidate 6 -Parallel 6 -LearningRate 0.30 -Sigma 0.10 `
    -ActionMargin 0.25 -StopOnHit
```
