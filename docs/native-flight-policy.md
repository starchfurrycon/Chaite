# 原生飞行模型：Demon Wings 明确子集

这是受限机动校准，不是“所有翅膀都已支持”或 Boss 胜率证明。八组共 4800 帧固定原生竖直轨迹已通过局部配对及独立自递推检查；完整结果和适用构建见 VERIFICATION。

## 来源与边界

核对 Windows Steam 原版 Terraria 1.4.5.8 的 `Player.Update`、`JumpMovement`、`WingMovement`、`ResetEffects` 与装备表，元数据只读，不分发原版程序集或反编译源码。另实际读取[官方社区 Wiki 的 Wings 页面](https://terraria.wiki.gg/wiki/Wings)及其滑翔、飞行时长和加速度章节；Wiki 中的源码引用部分是 1.4.5.6，因此精确时序以本机白名单版本再核对。

首个明确 profile 是干燥、正重力、基础 5.01/15 普通跳（可带云瓶），Demon Wings 的逻辑 ID 1，可带 `rocketBoots=2` 的火箭靴机制，基础容量为 100 翼时长；实际装备火箭靴时才计入 7 火箭资源，未装备也能观察到的原生默认上限 7 不代表可用续航。原生测试具体装备是 Demon Wings 492 与 Lightning Boots 898。相同火箭逻辑 ID 不代表所有鞋子的水平性能相同；横向速度仍读当前玩家实例。

Reader 使用只读编译访问器，保存真实计数、释放状态和资源，不读取可能已被另一玩家更新的静态 `jumpSpeed/jumpHeight`，不设置玩家资源。坐骑、钩爪牵引、绳索、羽落、倒重力飞行、其他翼、强化跳、其他额外跳、异常状态、正在执行的火箭批次等不属于这个已知 profile；不能把未知状态当作免费飞行。

## 有界的一 tick 转移

顺序是：清 `justJumped`、地面云跳恢复、水平移动、普通/云跳、资源恢复、翼推进、火箭转换、火箭恢复/批次、未推进时的滑翔或普通重力，最后碰撞与位移。候选路线仍每个原生 tick 推进状态，威胁评分可以使用较稀疏的采样。

- 普通保持计数从 1 减到 0 的同一 tick 就可以进入翼推进；最后一个翼时长单位仍完成该 tick 的推进，不再叠加普通重力。
- Demon 先减 0.1 纵速，再根据已经改变的速度分支：仍在下落额外减 0.5，慢速上升额外减 0.1，上升上限为基础跳速的 1.5 倍。不是固定统一加速度。
- 腾空时火箭余量乘 6 转为翼时长，转换发生在本 tick 的翼推进判定之后。常见 100+42=142，但必须读实际余量；已经转换的 142 在火箭为 0 时不能被错误截回 100。
- 无推进而按住跳、正在下落时，重力和通常的下落上限均为原来的三分之一；按住向下键（`controlDown`）可绕过小上限。翼耗尽后仍可以滑翔。松跳保留已有上升惯性，再施加普通重力。
- 原生翼资源恢复要求实际的零纵速与释放状态，或原生自动跳分支；火箭资源恢复的条件不同。单纯射出钩爪不等于抓住平台，不能预支补充。
- 火箭资源是推进批次，不是游戏 tick。Core 保留有界的批次语义，但当前 Reader 不会把已经在火箭批次中的玩家标为本次已校准的 Demon 起始状态，更不据此声明无翼火箭靴通过实测。

## 验证方式与限制

离线回归分别覆盖释放、云跳重按、耗尽、资源转换与归一化、落地恢复、Reader 拒绝未知状态、优化/参考规划器一致性。原生 fixture 使用无 Boss 的隔离副本与预声明输入，逐帧记录实际 `prePlayer/preJump/postJump/preWing/postWing/postPlayer`；独立 x86 oracle 同时检查真实入口状态的一 tick 配对及只初始化一次的完整 600 tick 竖直自递推，不在中途用原生状态重置模型。未调用 WingMovement 时不得伪造观察记录。Reader 的离线访问器检查与这些运动轨迹不等同于完整游戏适配器验收。

这仍不是完整的横向/斜坡/液体/碰撞地图/所有机动工具模型。实际 Boss 战还必须用同一构建独立验证，单元测试和飞行微测都不能代替逐 Boss 多种子通关证据。
