# 克苏鲁之眼：原生阶段驱动的跑道模板

本轮增加的是可检查的专用状态机，不是对所有场地/装备无伤的证明。原生实战胜负、受击、死亡和延迟仍以冻结代码后的隔离引擎报告为准，快照回归不能代替实战。

## 实际读取的来源

- [官方社区 Wiki：Guide:Eye of Cthulhu strategies](https://terraria.wiki.gg/wiki/Guide:Eye_of_Cthulhu_strategies)，通过 MediaWiki `action=parse&prop=wikitext` API 实际读取。指南支持“长而平坦跑道 + 跑鞋 + 保持直跑”的基础应对，指出云瓶可以帮助躲冲但良好场地下并非必须；多层平台切换和史莱姆坐骑弹跳是不同模板。没有拿未观看的视频作为证据。
- 原版 Terraria **1.4.5.8** 原始程序集 SHA256：`960A03BFF6050CF7BE16DFC1A7B19E10FC2C4F8F835A6A3B135A50DD9E6BA2F3`。
- 使用已有 `tools/research/Inspect-MethodIl.ps1` 仅读 Mono.Cecil 元数据。克眼 AI 没有独立 `AI_004` 方法，真实入口是 **`Terraria.NPC.AI()` 的 `aiStyle == 4` 分支，IL 041a..2c14**。
- 跳跃依据 `Terraria.Player.JumpMovement()`，控制器复用本轮 `JumpMotion` 纯模型，不调用游戏跳跃方法来“试跳”，不改变 AI 或人物属性。

## 真实阶段与时序

| 原生状态 | 含义与重要边界 | 本模板的用途 |
| --- | --- | --- |
| `ai0=0, ai1=0` | 第一形态追踪，普通约 600 tick、专家约 210 tick 后启动冲刺序列 | 建立跑速和跑道方向，引导后续冲刺 |
| `ai0=0, ai1=1` | 第一形态发射冲刺的单次状态 | 保持预备出口，不能把尚未更新的速度当成新冲刺轨迹 |
| `ai0=0, ai1=2` | 首形态冲刺；`ai2<40` 直冲，随后普通速度乘 .98，专家再乘 .985 | 直冲期间锁定出口；观察进入刹车后才允许恢复 |
| `ai0=1 / 2` | 加速旋转 / 减速旋转，各约 100 tick；本体移动乘 .98 | 独立变形恢复窗口，不能仅按生命值粗分两阶段 |
| `ai0=3, ai1=0` | 第二形态追踪；低于专家 12% 时原生转入重新取位 | 稳定跑道引冲或低血重新取位应对 |
| `ai0=3, ai1=1 / 2` | 二形态普通冲刺发射 / 执行；执行满普通 40、专家 50 tick 开始 .97 减速，专家再乘 .98 | 不用速度跨过 7/9 px 的瞬间触发策略切换 |
| `ai0=3, ai1=3 / 4` | 快速冲刺发射 / 执行 | 等待实际发射速度，再承诺同一出口 |
| `ai0=3, ai1=5` | 朝玩家下方约 600 px 重新取位，约 70 tick 后再发起快速连冲 | 不是“血少所以现在一定在冲刺” |

首形态普通冲刺序列每次总计普通 150、专家 100 tick，三次后返回追踪。第二形态普通冲刺每次普通 130、专家 90 tick，三次后返回追踪或进入专家连冲分支。主要证据：`0e9e..11a4`、`1c64..2017`。

变形阈值是普通 `life < lifeMax * .5f`，专家/大师 `.65f`，原生使用 **`conv.r4` + `ldc.r4` + 乘法**（`11a4..1209`）。快速阶段低于 12%、4% 则使用 **`conv.r8` + `ldc.r8` + 乘法**（`0429..0474`）。不能把它们全部替换成单精度生命比值；x86 中间精度会影响数学上刚好等于百分比时的比较结果。回归同时覆盖整数邻居和同序 IL 边界比较。

专家快速冲刺的直冲计时通常为 20，低于 4% 改为 10。到达计时门槛且距离玩家小于 200 px 时，原生会将计时减回一 tick，继续直冲；之后才乘 .95 刹车，达到门槛 + 13 后进入下一次，`ai3` 控制最多五次及其他条件分支（`26e1..284a`）。因此本模板信任真实 `ai2`，不自行用“进入阶段已经过了 20 帧”替代它。

快速发射的向量用到了玩家当前速度及随机扰动（`21f6..2276` 等后续分支）。本模板不会读写 RNG 或猜定下一条随机轨迹，而是在观测到 `ai1=4` 后采样真实发射速度。低于 35%、普通三冲后低于 50% 等进入快冲的条件同样交由实际 AI 状态确认，不靠速度大小推断。

## 控制闭环

1. **引冲。** 跑道方向在初始状态建立，追踪期间保持跑速。跑道需要回转时，只在真实追踪、变形或刹车恢复阶段尝试，先以当前横向运动模型检查未来 24 tick：脚印始终在实际连续地板上，回转走廊也不能与 Boss 的观察轨迹交叠。
2. **承诺退出。** 发射状态保持预备方向；进入真实直冲状态才记录发射向量。直到观察到刹车/重新取位，不因 Boss 穿到另一侧、瞬时速度下降或通用环绕误差而反转。遇到跑道尽头按真实减速度刹车，不硬反转穿过 Boss。
3. **条件起跳。** 只有正常重力、已知普通跳模型、真实可释放/起跳状态和连续地面才考虑普通持跳。对近水平且不从头顶俯冲的真实冲刺，用最长 24 tick 的地面轨迹与持跳轨迹检查：地面轨迹确有威胁、持跳轨迹全程留有净空、起跳至少有四 tick 提前量，才进入一次持跳。
4. **恢复。** 起跳后只维持真实剩余持跳计数，计数结束即松键，回到地面跑道子循环；不将云瓶或未知飞行资源变成持续上升力。Boss 变形或刹车时恢复路线；已有足够远距离时可以松键输出，不无限跑远。

`UseExplicitMovement` 与 `JumpAction` 明确表示方向 0 / 松键 / 持跳，防止通用垂直追踪把“Boss 在上方”变成持续乱跳。紧急碰撞评估仍可覆盖专用路线，不宣称专用指令具有物理免伤能力。

## 跳跃模型与明确未完成项

原生持跳且 `jump>0` 时，每 tick 重设 `vy=-jumpSpeed*gravDir` 并扣计数（`JumpMovement 057b..0607`）；释放会清 `jump` 并重新置 `releaseJump`（`1ebe..1ed3`）。云瓶需要剩余资格和释放边沿，消耗后赋予 `(int)(jumpHeight * .75)` 的持跳计数（`0631..06fc`、`088b`、`1aa2..1b16`）。

本控制器复用 `JumpMotion.ResolveControl / ApplyJump / ApplyGravity`，包括持跳、重力后位移和空中无法继续积累某些跑鞋加速的差异，不再采用一次向上冲量的近似。**本版 Eye 不主动要求 Cloud 动作**：原生云瓶的接线/微测试与其在每个克眼连冲中的可靠触发策略是两回事。平台间换层、钩爪快速复位、坐骑弹跳、反重力、其他二跳类型也尚未包含在此专用模板。

## 范围、性能与验证边界

- 入场政策为横向净空 1200 px、纵向 240 px、跑速 5.5 px/tick、基础远程输出 18 DPS，另受通用难度余量约束。这不是最小场地的数学证明。指南的双层长平台模板建议显著更长，不能声称目前短跑道等同于那套打法。
- 常规世界普通/专家/大师是目标范围；特殊种子、液体、坐骑或未知跳跃模型不会获准本模板的计划普通跳。其他分支仍属于需要单独验证的范围，不能因为相位名带模式后缀就冒充已验证。
- 没有新增逐帧地形扫描。复用有限的地板区间和既有目标快照；常态只做固定比较，回转或起跳评估各最多 24 次标量推进，无路径树和额外集合分配。
- 回转/起跳只基于当前观测速度，不重放 Boss 的完整未来 AI，不假设知道随机后续冲刺。局部净空也不是全场地地图证明，跨阶段的未来风险由后续快照持续校正和紧急层处理。
- 回归覆盖阶段/时钟、原生浮点阈值、锁定方向、恢复回转与拒绝、实际制动、普通持跳生命周期和开火保护；尚不能据此声称无伤、低装备稳过或所有变种完整适配。
