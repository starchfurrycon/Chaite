## 0. 直接回答四个问题

| 问题 | 原生答案 |
|---|---|
| **锁定发生在第几帧** | 在**悬停状态的最后一帧**：`ai[2] += 1f; if (ai[2] >= num3) { ... velocity = Normalize(player.Center - center) * num7; }`。方向一次性算定，之后状态 `1/6/11` 不再重算——**你说的"锁定后不改变"在源码里成立**。 |
| **冲刺持续** | 状态 `1/6/11` 各跑 `num6` 帧（`ai[2]` 从 0 每帧 +1，退出条件是 `ai[2] >= num6`，所以 `ai[2]` 走过 1..num6，共 **num6 帧**）。锁定那一帧写下的 `velocity` **不在当帧生效**——`NPC.Update` 的碰撞与位置积分在 `NPC.AI()` **之前**运行，所以 AI 里写的速度要到**下一帧**才被积分；锁定帧本身走的是锁定前的悬停速度。因此冲刺以 `num7` 位移 **恰好 num6 帧**：专家一阶段 28 × 17 = **476 px**（与 `FishronWingScript.cs` 的引擎实测值一致）。 |
| **冲刺间隔** | 一阶段 = 悬停 `num3=40` 帧 + 冲刺 29 帧 = **69 帧一个来回**。二阶段 = 27+30=57。三阶段 = 30+26=56。**与你之前的观察一致。** |
| **招式间隔（非冲刺）** | 泡泡 `num8=80`；鲨鱼龙卷 `num12=90`；旋转鲨鱼 `num16=120`；侦察传送 `num13/num14=180`。 |

### 分派逻辑（决定打几次冲刺）

状态 `0`（一/二阶段组）：
```
ai[3] 0..9   → 冲刺 (state 1)
ai[3] == 10  → ai[3]=1; 泡泡 (state 2)
ai[3] == 11  → ai[3]=0; 龙卷 (state 3)
```
所以在 `ai[3]=0,2,4,6,8` 上打 **5 次冲刺**（`num2=5`，一阶段），
打完第 5 次后 `ai[3]=10` → 泡泡 → `ai[3]=1` → 龙卷 → `ai[3]=0`，循环。
`flag6`（狂暴）会把 `num2` 变 3，并把泡泡降级成龙卷。

状态 `5`（二阶段组）：
```
ai[3] 0..5  → 冲刺 (state 6)
ai[3] == 6  → ai[3]=1; 泡泡 (state 7)
ai[3] == 7  → ai[3]=0; 龙卷 (state 8)
```
**3 次冲刺**（`num2=3`）。`flag2`（三阶段血线）改用 `state 9`。

状态 `10`（三阶段组）：
```
ai[3] in {0,2,3,5,6,7} → 冲刺 (state 11)
ai[3] in {1,4,8}       → 瞬移 (state 12)
ai[3] == 9             → 旋转 (state 13)
```

## 3. 悬停的追踪目标

状态 `0/5`：`Normalize(player.Center + (ai[1], -200) - center - velocity) * num5`，
其中 `ai[1] = 300 * sign((center - player.Center).X)`（进入时算一次）。

状态 `10`：`ai[1] = 360 * sign(...)`。

加速是**按轴**的：`num4` 加到 `velocity.X`/`velocity.Y`，并且当速度与目标符号相反时
**再加一次 `num4`**（即反向时双倍加速）。

## 4. 狂暴（enrage）

```
flag6 = player.position.Y < 800
     || player.position.Y > Main.worldSurface * 16
     || (player.position.X > 6400 && player.position.X < Main.maxTilesX*16 - 6400);
```

注意第三项是 **AND**（"在海洋外侧条的里面"），不是 OR。

狂暴效果：`num3=10`（悬停只剩 10 帧）、`damage=defDamage*2`、`defense=defDefense*2`、
**`num7 += 6f`**（冲刺更快）。狂暴还会把 `num28/num33==2`（泡泡）改判成 `3`（龙卷）。

## 5. 对实验台的直接影响

1. **本实验台的狂暴判定是错的**。旧代码写的是
   `y < 800 || x < bandLeft || x > bandRight`，而原生是
   `x > 6400 && x < maxTilesX*16-6400`。实验室跑道在 1000..6000，按原生
   **永远不狂暴**；按旧代码则几乎总是狂暴。
2. **冲刺位移恰好 num6 帧**（专家一阶段 28 × 17 = 476 px）。锁定帧写下的速度
   **下一帧才生效**，因为 `NPC.Update` 的位移积分在 `NPC.AI()` 之前。这一条是被
   `FishronWingScript.cs` 记录的引擎实测 476 px 反向确认的——如果锁定帧也算位移，
   就该是 493 px，与实测不符。
3. 一阶段完整循环是 `5 次冲刺 → 泡泡(80) → 龙卷(90) → 传送(180) → 回到冲刺`，
   不是"一直只有冲刺"。实验台把泡泡/龙卷做成可选威胁是对的，但**状态顺序**必须一致。
4. 状态 `7` 里 `Main.rand` 用于 `ai[3]`（鲨鱼速度倍率），这是**唯一影响战斗的随机数**
   ——它改的是鲨鱼速度，不改 Boss 自身轨迹。
