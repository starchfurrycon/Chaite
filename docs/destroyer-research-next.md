# Destroyer：失败证据与下一步有界闭环

本文是只读研究，不是已经落地的控制器，也不构成通关、无伤或最低机动性证明。本轮没有修改生产代码、装备、场地、Boss AI、伤害或游戏存档，没有重新运行原生战斗。Eye／Queen 的改动与后续飞行模型验证不能倒推为这场旧 Destroyer 运行已经得到修复。

`tools/GameProbe.cs` 中 `if (p.statLife < lastLife) hits++;` 统计一次原生更新后生命下降的帧，包括环境伤害。日志没有逐次伤害来源，也没有每帧结构化动作／策略阶段轨迹。因此不能把这 23 帧分摊成“几次头撞、几次激光、几次跌落”；每 60 tick 的相邻生命差还会混入再生和治疗。

### 最后一击已经有直接来源

`game-probe.log:183`：

> 2026-09-10T07:48:09.2983229Z NATIVE_DEATH Chaite Lab was brutally dissected by Werewolf.

对应栈为 `Player.Hurt → Player.Update_NPCCollision → Player.Update → Main.UpdateWorld_Players`。最后一击是**狼人接触伤害**，不是 Destroyer、Probe、激光或摔落。原生死亡文本和调用栈是直接证据；不能因最后一击来自狼人就否认此前 Boss 战的压力。

### 平台范围、资源与实际落点

场地实心地面为 tile X `[800,3400)`、Y 500；两行单向平台为 X `[1850,2350)`、Y 460／420。换算像素：

- 平台实际横向范围只有 X `[29600,37600)`，高度 Y 7360／6720。
- 42 px 高角色站在两层平台时，位置 Y 分别为 7318／6678；地面站立 Y 为 7958。
- 初始玩家位置为 `(33600,7958)`。地面横向范围远大于平台，离开平台范围后仍然有低处地面，不意味着仍有空中恢复支点。

这场运行的 127 个 `EngagedAlive` 抽样点（每 60 tick 一次）中，53 个 Y≥7800、17 个恰在 Y=7958、44 个 X 位于两层平台范围之外。它们只是**抽样点数量**，不能作全帧驻留比例。第一条位于平台范围外的抽样是 tick 5160：X=29499.41、Y=7903.776；后续最西到 X=25891.94。

## 2. 当前策略的结构性缺口

核对当前 `DestroyerStrategy`、`CombatPlanner.PatternVertical`、`TerrariaFacade.ReadTargetsAndThreats` 和 `ThreatSnapshot.BoundsAt`：

1. 高度目标是头部中心 Y−260，再施加 `FloorClearance=320`；没有固定、持续保留的上层平台返航锚点。头部上下运动和本地地面选择变化可能造成无益追高、平台范围漂移。这是代码可见的反馈风险，旧抽样轨迹与之相容，但没有逐帧策略日志就不能宣称已唯一归因。
2. 头部只在速度大于 8 px/tick 时做至多 30 tick 的线性最近接近检查。它不能覆盖从慢速转向／加速到钻出的完整危险过程，也没有模拟空气／钻地切换。
3. Probe 近距或数量压力会切换火力，但输出目标只允许 134／135／136／139。狼人等普通敌人虽然由 Facade 加入接触威胁，策略仍不会主动选作清场目标。不要误述为“完全没检测到狼人”。
4. **身体和尾部的移动预测存在确定的模型不匹配**：原生会直接改 position，同时把 velocity 清零；当前 Facade 原样读取 velocity，线性 `BoundsAt(t)` 因而把它们当作未来静止矩形。这不是装备不够，也不能仅靠增大躲避半径解决。

第 4 项是应优先单独校准的观测／预测问题。还不能根据旧日志断言它具体造成了哪一次受击。

## 3. 已核对的 1.4.5.8 原生机制

Windows Steam 原版 x86 程序集 SHA256：`960A03BFF6050CF7BE16DFC1A7B19E10FC2C4F8F835A6A3B135A50DD9E6BA2F3`。通过 `tools/research/Inspect-MethodIl.ps1` 仅读元数据，没有执行被检查方法；不在项目中分发原版程序集或完整反编译源码。

### 身体链不是独立匀速物体

`NPC.AI_037_Destroyer` 的 `0b61..0dd1`：

- `ai[1]` 指向前节；正常单 Destroyer 间距以 `(int)(44*scale)` 为基准。
- 根据前节位置修正当前节的位置，转向随连接方向变化。
- `0d11..0d17` 显式设置 `velocity=Vector2.Zero`。
- `0d1c..0d3c` 直接给 position 加跟随位移。

因此，未来身体扫过的路线不能从原生 velocity 得到。最低限度的适配是记录相邻原生 tick 的同一实体位置差，作为**独立的运动学观测量**；绝不写回原生 velocity。只用位置差作短时线性外推仍然不能准确表示卷曲身体，完整链预测应读取前节关系、尺寸／scale 和更新顺序。

同槽位同类型不保证始终是同一 NPC；必须处理失活后重生、召唤新链、帧间隔、前节身份变化、异常大跳变。不可对首帧、漏帧、重用槽位或断链填造精确速度。Mechdusa 的特殊间距分支不是这里已校准的普通链。

### “离屏空气视作实体”不是屏幕判定

`AI_037_Destroyer 0614..07f6` 的材料检查包含：活动实心块、活动单向平台且 `frameY==0`，或液体量大于 64；需要与 NPC 矩形重叠。因此不能把平台当作对它完全无效的空气。

没有上述材料时，`0865` 先置 `localAI[1]=1`。随后 `0882..0952` 对头部 134 还有一层回退：当头部 position.Y 大于目标玩家 position.Y 时，检查头部矩形是否与**每位活动玩家左上位置为中心、±1000 px 的 2000×2000 矩形**相交；若没有相交，就启用钻地式转向，即使该处没有物块。

这不是相机、分辨率或可见窗口检测；Wiki 对“离屏”的简述不能直接写成摄像机条件。`localAI[1]` 的赋值早于后面的回退，单读它也不能完整代表最终采用的材料／钻地分支。多人状态下其他活动玩家也可能影响结果。

### 普通空气分支与激光不是同一种预测问题

`0961`、`0a28..0b4a`、`0dd1..0f45` 可见普通头部空气分支基准：速度尺度／下落上限 16、横向加速 0.1、转向量 0.15；目标／头部中心有 16 px 网格取整；空中 vy 每 tick 加 0.15、上限 16，并有低总速度、达到下落上限、vy>4 时的不同 vx 调整。For the worthy 有参数变化，Mechdusa 也有独立分支。

这里**没有完成完整钻地转向分支的精确重写或原生轨迹验证**，不能宣称可以任意长时间精确预测头部。开始可使用明确的普通空气短窗与局部材料失效检测，未知分支只给保守包络。

`03aa..0614` 的身体激光分支只属于 135：计数每 tick 加 `rand.Next(4)`，和新抽出的 `Next(1400,26000)` 阈值比较；满足之后重新选目标并做实际 `CanHit`。基础速度 8，目标点和速度还有随机扰动，发射物 ID 100、初始 `timeLeft=300`。所以不能从一个计时器推断固定发射倒计时／精确未来射线。应优先跟踪已生成的真实弹幕；对尚未生成激光只作非精确的区域／停留风险，不伪造必然命中线。

### Probe 生成是受击触发，火力分配会改变压力

`NPC.HitEffect 2544c..25576`：身体 135 仍存活、非网络客户端、`ai[2]==0` 时，每次满足该分支的受击有 `1/25` 概率放出 Probe 139，并将 `ai[2]` 置 1。`IsMechQueenUp()` 时分母为 50；这里不是 Expert 倍率。不能把它写成所有身体固定周期自动吐 Probe，也不能据此预测下一次随机释放。

这与优先清 Probe 的指南相符：无条件扩大身体输出可能增加未清理的飞行单位，策略需要压力门限和恢复火力的滞回，不能只有“永远集火 Boss”。

## 4. 网络指南能提炼什么，不能照搬什么

实际读取官方社区 Wiki 的 [Guide:The Destroyer strategies](https://terraria.wiki.gg/wiki/Guide:The_Destroyer_strategies)，接口为 `api.php?action=parse&page=Guide%3AThe_Destroyer_strategies&prop=wikitext&format=json`。

对当前普通跑道／有限翼时装备可用的模板是：观察头部钻出，沿侧面避开其已形成的空中弧线，尽量保持在身体上方，不被逼到身体下面；清理 Probe，确认身体路线后才回地面或收心；宽而有层次的平台提供恢复支点。

指南的高空实心遮挡盒、沥青跑道、矿车或特定坐骑，是各自需要准备的独立模板，不能把其安全性或加速收益套到当前普通平台。尤其“高 150 格”不是任意飞到同高度即可免疫头部／激光，当前 fixture 也没有对应遮挡盒。穿透／范围武器建议只能指导**从实际快捷栏选择已有武器**，不能替换当前验证装备来掩盖控制器缺陷。

## 5. 建议实现的有界闭环

优先适用范围：普通独立 Destroyer、正重力、已观测正常平台／地面、已经原生校准的机动 profile。特殊种子、多机械 Boss、未知翅膀／坐骑不能自动继承“已验证”标签。

| 状态 | 进入与动作 | 退出条件／安全不变量 |
| --- | --- | --- |
| `AcquireAnchor` | 在有限局部地形中选定一段真实支撑面，保存其高度、左右可站范围和返航区；当前所在位置无法安全返回时选择可达的次级支点。 | 不能只保存“附近有地面”；横向停止距离、身体通道和到达所需资源都必须可行。 |
| `SupportedPressure` | 以支点为高度参照，短距离横跑输出；优先处理即将封路的 Probe／普通敌人。 | 不追随头部高度无限升高；在仍有回收余量时才离开支点。 |
| `HeadExit` | 头部逼近／上升威胁进入有限走廊时，选定侧向出口，必要时使用已经校准的跳／飞；出口在短窗内保持。 | 按原生制动距离和平台范围评估回头；头部跨过玩家 X 不导致即时反向横穿头部。 |
| `AboveChainTransit` | 利用已形成的头部空中弧线，从身体上方走向保存的返航区；飞行不是默认持续按住。 | 禁止计划性穿过身体链；剩余资源、惯性、滑翔和真实着陆时间同时满足，不等翼时归零才找地面。 |
| `RecoverAnchor` | 降落到已核实 X 范围内的支撑面，按原生释放跳跃／着地规则恢复资源；恢复中继续清近身威胁。 | 实际观察到着地与资源恢复才重回常态；发出钩爪或预测碰到平台不算已经恢复。 |
| `Reacquire` | 支点被破坏／超出可达范围、路径封锁、状态突变时，放弃失效路径，选有限备选支点。 | 保留 Boss 战会话，不因暂时失去闭环就误报胜利；也不能靠无支点持续追高假装正在恢复。 |

具体守卫应使用现有 `FlightMotion` 的明确 profile 与实际 native 资源，不再将 `max(wing,rocket)` 解释为完整可飞 tick。普通敌人的清场火力目标必须与 Destroyer 头部 `PatternTarget` 独立，避免为了打狼人就丢掉头部位置。救急层仍可打破期望动作，但必须返回同一支点／闭环，并记录为什么被打断。

状态机不是无伤保证：如果实际场地没有可达支点、机动不够或被多方向完全夹住，应诚实暴露“缺少安全恢复路径”，不能改玩家属性、忽略敌人或补平台。钩爪／冲刺／坐骑只能在各自原生能力与落点校准后增加独立转移，不能把一次发钩自动记为重新充能。

## 6. 低延迟实现次序与验证门槛

1. **先修观测再堆策略**：固定容量 NPC 运动历史，逐帧更新 identity、位置差和前节关系。身体短窗预测与原生位置回放独立对照；量测首帧、断链、零距、槽位复用和新 Boss 生成。未知运动不冒充零速度。
2. **共享一次环境／链预测**：每原生 tick 建一次有限期头部／身体轨迹或保守包络，所有少量玩家候选共用；不在每候选、每身体、每未来步中重复反射或扫描整图。身体链推进应核对原生槽位更新顺序，不直接假设同步更新所有节。
3. **局部有效性与保守误差**：地形只查头部扫掠边界和少量返航平台，地形变化／脱离局部窗口时失效。前节运动、目标玩家未来位置或材料切换未知时扩大有限短窗包络，不伪称长时精确路径；因包络过宽拒绝一切动作也是需要检测的失败。
4. **先单项原生微测，再战斗**：固定输入且不改 Boss AI 的短轨迹比较身体位置、空气段切换、平台着陆／释放恢复；离线回归包括“已在平台高度却在平台 X 范围外”、翼时不足返航、头部慢速转向、普通敌人封路、Probe 压力滞回、退出方向持有。
5. **战斗日志补齐因果链**：在未来 harness 中逐真实伤害事件记录来源种类／实体 ID、伤害前后生命、原生 tick；同时记录策略阶段、支点、资源、计划与实际动作的紧凑事件流。它是下一步要求，本文没有修改 GameProbe。Boss 根部死亡、玩家死亡、脱战严格区分。
6. **同构建、固定装备复跑，再扩展随机种子／难度**：先在本次原场地原装备证实失败是否改善；不能凭一次胜利或离线回归称作稳定通关。旧 2.2304 ms 的 p99 是比较基线，不是给新算法的测量结果。保留均值／p95／p99／最大值及窗口、样本数和计时口径，分别评估策略与完整原生更新。

这一顺序以短时有界预测服务长期恢复闭环：不做世界级暴力搜索，也不把当前一步安全等同于后续可恢复。
