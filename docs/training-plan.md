# 小模型训练方案（按路线）

> 用户指示（第 16 轮）：固定状态机的战斗策略已到上限。准入、操控、终止目标状态都已成熟，
> **唯一剩下的缺陷是战斗策略**，因此改为按路线训练小模型。
> 训练耗时较久：**代码验证无误后启动，启动后不持续监视。**

## 0. 不可违反的三条既有规则

1. **两组测量的 `probe-manifest.json → InputCoreSha256` 必须不同**，否则比较无效
   （§21 事故）。
2. **wave 运行期间绝不改动 / 重新编译 Core**（§21、§26 两次实测）。
3. **失败的运行一律保留，不删不改**（`artifacts/` 为 gitignore）。

## 1. 核心架构决定：**训练期间不重新编译**

策略参数存放在**数据文件**里（`artifacts/training/<tag>/params.txt`），
探针启动时读取。于是一代训练只是**改写一个文本文件**，不需要 rebuild：

- Core 的 `InputCoreSha256` 在整个训练期间**恒定**，所有代之间的比较天然有效
  （直接消除 §21/§24 那类"源码改了但 DLL 没变"的陷阱）；
- 每代省掉一次 build（约 40 s），且不存在"build 期间 wave 在跑"的禁忌冲突；
- **只有策略拓扑或特征集改变时才需要 rebuild**，那种情况视为新训练、换新 tag。

## 2. 策略（"小模型"）

- 拓扑：固定小型 MLP，**单隐层 48 → 32**，四组输出头：
  `horizontal(3)`、`vertical(3)`、`jump(2)`、`dash(2)`，各自 argmax。
  参数量约 **1.8k**，文件小于 30 KB。
- 全部输入都已在现有计划上下文里可用（`FormulaScriptInput` + `snapshot`）：

| 特征组 | 维度 | 说明 |
|---|---|---|
| 相对位置 | 4 | `dx/900, dy/900`，以及 `|dx|,|dy|` 的归一化 |
| 相对速度 / 玩家速度 | 4 | 追击与脱离判断 |
| 距离 | 1 | `/900` |
| 原生状态 one-hot | 14 | `ai[0]`，猪鲨 0–13 |
| 原生计时 / 序列 / 形态 | 3 | 攻击节拍 |
| 最近 4 个威胁投射物 | 16 | 相对位置 + 相对速度 |
| 场地边界接近度 | 2 | 左右边界 |
| 上次动作 | 8 | 避免抖动 |
| （可选）本体速度 | 2 | |

- **输出即现有计划的动作字段**。

## 3. 适应度（每局一个标量）

```
win                       -> +1.0
否则                       -> damageDealt / 98000  -  0.5 * (hits / 14)
```

- 直接用**掉血比例**而不是 tick 数，避免"苟活"拿分；
- 受击惩罚系数取 `hits/14`（14 次即死），使"少挨一次"约等于多打 3.5% 血量；
- 每代用 **K=4 个不同种子**求平均，且**每代重新洗牌种子**，防止过拟合。

## 4. 优化器

- **(1+λ) ES / 镜像采样**，λ=16，σ 从 0.10 起、按 1/5 成功规则自适应；
- 适应度做**秩归一化**（排名而非绝对值），对离群局更稳；
- 每代保留最优，并在 `params-best.txt` 落盘（崩溃可续）。

## 5. 评估与并发

- 单局探针约 **28–33 s** 墙钟（实测 20 局 = 17 min）。因此：
  - 串行一代 = 16 候选 × 4 种子 × 30 s ≈ **32 min**（太慢）；
  - **并行 K 路**（K=4）≈ **8 min/代**，100 代 ≈ 13 h。
- **启动前必须先烟测"并发隔离探针是否安全"**：跑 2 路并发 × 2 种子，
  确认两路的 `result.json` 与串行时**逐位相同**。若不相同，则退回串行并把
  λ 降到 4、种子降到 2，接受更慢的训练。

## 6. 验收

- **保留种子**：训练种子与验收种子**不相交**（训练用 1–200，验收用 1001–1060）。
- 每 10 代在 **20 条保留种子**上评估一次，记录胜率与 Wilson 下界。
- 最终验收口径与目标一致：**≥40 条独立保留种子、95% Wilson 下界 ≥90%**，
  并且与固定状态机基线在**同一场景/路线上**对比。

## 7. 产物（全部保留，失败不删）

```
artifacts/training/<tag>/
```

## 8. 启动前必须确认的四项（否则不算"确认无误"）

1. 探针**如何选择路线 / 脚本**（能否新增 `learned-<route>` 而不改下游管线）；
2. 策略文件缺失 / 格式错误时**必须明确失败**，而不是静默退回固定状态机
   （静默回退会污染整轮训练且极难发现）；
3. **并发探针烟测**（见 §5）逐位一致；

   `bossLifeRemaining`、`(单个对象).Count` 返回 `$null` 两个坑）。

## 11. 第 19 轮：适应度的"标杆"、时间修正、以及噪声这一点

### 适应度必须对着标杆读，而不是对着 0 读

用训练器**同一个公式**（`damage/98000 − 0.5·hits/14`）回算固定状态机在
**46 条唯一种子**上的适应度：

| | 适应度 |
|---|---|
| 固定状态机 平均 | **0.3885** |
| 固定状态机 中位 | 0.3988 |
| 最好 / 最差 | 0.5357 / 0.2737 |
| 随机初始化（gen1 父代，种子 8/58/40/17） | **0.1637** |

两个结论：

1. **学习者起点（0.164）远低于固定状态机（0.389）**——它必须先爬过 0.389
   才算"不落后于手工状态机"，这条线必须画在日志里，否则适应度曲线无法解读。
2. **胜局 = 1.0**，与 0.389 之间有巨大落差，所以这个指标是**奖励真正的胜利**，
   而不是奖励"伤害刷得好看但不赢"——这一点是对的。

### 时间修正（诚实更正上一轮的估计）

gen1 父代（4 种子）实际耗时约 **3 分钟**（含每次 wave 的准备开销），
因此一代 ≈ 17 分钟，**60 代约 17 小时**，而不是我上一轮估计的 8–9 小时。
方向不变，但数字要更正。

### 噪声与它的护栏

每代只用 4 条种子，而固定状态机自身的适应度跨度是 0.27–0.54，
所以单条种子的噪声远大于 σ=0.10 扰动带来的真实增益——
"更好就接受"这条规则有被噪声主导的风险。

缓解措施**已经内置**：**代内所有候选与父代使用同一批种子（common random
numbers）**，因此候选之间的比较是**配对**的，噪声会大幅抵消，这也是 ES 的标准做法。
真正的护栏是**验收口径与训练口径分离**：接受与否看 40 条**不相交的保留种子**
（1001–1040，每 5 代一次）。若训练适应度上升而保留种子始终停在 0 附近，
就会**当场暴露过拟合**，而不是等到 17 小时后才发现。
