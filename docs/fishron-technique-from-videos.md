## 0. 视频像素/OCR 重建的实测走位（第 150 轮新增，业主指定方向）

业主在轮 150 明确指示：自然语言的描述不足以改善现状，应从**视频关键帧 OCR 与像素识别**重建打法。
已对本地缓存的第四个视频（`BV1Rf3o6EEx7` = `tmp/bili/D-nohit.mp4`，无伤演示，232 s / 1280×720 /
30 fps / 6961 帧）完成首轮重建。以下数字是**从视频像素实测**得到的，不是转述。

### 0.1 方法：把视频变成可计算数据

像素分析无法直接认出精灵（本项目使用的模型无视觉输入，且精灵色块与 HUD 图标混淆），但发现了一条
**更好的数据通道：游戏自身的 HUD 文字**。泰拉瑞亚的深度计把玩家的**绝对世界坐标**以文字画出，
OCR 即可得到精确轨迹，完全不需要追踪精灵：

```
深度计数字条位置       x 1061..1148, y 442..459   (1280x720 帧内)
OCR 得到              "3880以西"  -> 世界 x = 3880 (格)
                      "278的地表" -> 深度 278
同时可读              "每秒1122伤害"(DPS)、"37mph"(水平速度)、"附近有N个敌人"
```

1 Hz 采样 232 帧，成功解出 **218 个坐标点**。10 Hz 数字模板匹配尝试**未通过校验**（HUD 字体的笔画
在二值化后断裂，连通域把一位数字拆成多块），已放弃；1 Hz 精度已足以回答"何时转向、在哪里转向"。

### 0.2 实测结果：这就是"W 走位"的确切形状

**主要转向每隔约 11 秒发生一次**，且转向点固定在场地两端：

```
转向间隔(s): 11, 10, 9, 11, 14, 11, 12, 9, 11, 11, 10, 12, 11, 11, 11, 11
（1–2 秒的短间隔是采样抖动与个别 OCR 跳变，如 t=214 的 93782，已排除）

东端转向 x ≈ 3990 .. 4093
西端转向 x ≈ 3553 .. 3648
```

由此得到三个**可直接实现**的事实：

1. **单程跨度 ≈ 530 格（8480 像素）**，即玩家每一趟都**横穿整个场地**到对面那端。
2. **一趟约 11 秒**；实测水平速度中位数约 **50–55 格/秒**，与 HUD 的 mph 读数一致。
3. 玩家始终贴着**水面附近**（深度 218–305 格），不是在大深度空间里机动。

### 0.3 与当前电路的差距（关键）

当前电路在飓风窗口内只保证 **760 px（47 格）** 的逃离半径，而视频里的打法是**跑到对面那端（约 530 格）**。
也就是：**当前电路的"逃离"比真实打法小了一个数量级**——它是局部闪避，而正确动作是**整场横穿**。

这解释了此前"半径 760 已是最优、放大反而更差"的测量为何与视频矛盾：放大半径会让 `tornado-clear`
分支的 `return` 抑制起跳 20 tick 前摇的次数大增，**逃离半径与起跳抑制被耦合在同一个分支里**。
因此正确的下一步不是单纯放大半径，而是**把"跑到对面"与"起跳前摇"解耦**（轮 150 已完成的内存/
响应/半径三拆分，使得 `CHAITE_TORNADO_RECALL` 可以单独扫而不同时延长起跳抑制）。

## 1. 出招规律（评论 367 赞，与原生 `AI_069_DukeFishron` 的 `ai[0]` 状态机一致）

```
一阶段   5 次冲刺          -> 吐泡泡
        再 5 次冲刺        -> 原地放水龙卷
二阶段   3 次冲刺          -> 转圈吐泡泡
        再次冲刺           -> 释放追踪水龙卷
三阶段   身后冲刺 1 下
        再身后冲刺 2 下
        最后连续冲刺 3 下
        （周而复始）
```

前两阶段之间还有一条常被引用的观察：**二阶段除了龙卷和泡泡，猪鲨其余攻击和普通冲刺是一样的**。

## 2. 三阶段的瞬移规律（评论 618 赞，作者置顶补充）

> 进入三阶段后，公爵记下此时玩家处于它的哪一侧，然后向玩家进行 **1 次冲撞**；接着瞬移到刚刚记下的
> （这次冲撞前相对于玩家位置的）**同一侧**，紧接着 **2 次连续冲撞**；第二组冲撞完成后的瞬移位置会发生
> 改变，瞬移到与之前瞬移"对于玩家"**不同的一侧**，然后 **3 次连续冲撞**，完成一次循环。

可总结为：**瞬移 → 1 冲 → 瞬移 → 2 冲 → 瞬移并换另一侧 → 3 冲**。

即"每当改变方向时会根据上一次出现的位置以玩家为观测方'始终使玩家处于中间'对称式地改变方向并瞬移"。

**这条对我们最重要的含义**：三阶段的冲刺节奏是**可预知的固定序列**，因此三阶段的躲法是**背板 + 克盾
迎击（跳绳）**，不是纯反应。业主说的"三阶段克盾跳绳"就是它。

## 3. 转阶段控制（评论与弹幕，多来源一致）

- **停火控血**：`注意观察血条（50% 和 15%）及时停火，让猪鲨在版边切阶段，给自己留足容错`
- **进三阶段要控血**：`进三阶段要控血，这个公式不太行`
- **龙卷落点**：`尽可能通过走位让猪鲨的鲨龙卷稳定在平台两端处释放，尽可能不要让他中间释放`；
  并且 `如果猪鲨的鲨龙卷有一个是在海边放的，那下一个鲨龙卷也会在海边释放`。

**这直接否定了我第 124 节的"结构性不可达"推理。** 我当时认为"哪些攻击循环出现"是 DPS 的函数、
玩家无法干预；而上面的做法说明**玩家可以在阈值处停火，主动选择转阶段的时机与位置**，从而把危险招式
（追踪龙卷、鲨鱼射弹）推到对自己有利的场地位置。我们已经实现的"转阶段停手"（`CHAITE_SIM_PHASE_HOLD`）
就是这条规律的第一个粗糙版本，但它是"阈值处有危险物才等"，而不是"在阈值处主动把 Boss 拉到版边再打"。

## 4. 前两阶段的走位

- **W 型 / V 字走位**（业主此前也说过 W 走位；弹幕：`一二阶段用 w 型走位还是挺好打的`）
- 莉莉丝项链方案的原文：一阶段无脑按住 W 遛狗；二阶段因为猪鲨加速，**走位要变成 V 字形**，
  到平台两端用机动从猪鲨**头顶跳过去**；**不要在猪鲨想转阶段时擦头皮跳过去或从底下跑过去，会被创**。
- **方向变换的时机**：`为了完美规避冲撞，方向变换的时机很重要，不然闪快闪慢都会被挤压容错`
- **本质**：`本质就是上下跳，不要多少技术`——即**上下（垂直）机动是主要手段**，这与我们实测
  "垂直分量缺失（需要约 -10 px/tick，实际约 0）"完全吻合。

## 7. 下一步实现清单（按优先级）

1. **阈值控血 + 版边转阶段**：在 50% 与 15% 阈值前主动停火，把 Boss 引到场地一端再放伤害过阈值，
   让下一个龙卷/鲨鱼在版边生成。这是唯一一条"玩家可干预攻击循环"的规律，也是第 124 节错误的根源。
2. **垂直分量**：把逃逸的垂直指令在整个到达窗口内固定为逃逸符号，并且用实测速率而不是假定值。
3. **克盾时机**：把冲刺按"时距接触"排到身体到达那一帧（§128 已找到 ttc=6/10 有效）。
4. **三阶段背板**：按 1-2-2-3 的固定节奏预判冲刺，而不是反应。

## 8. 已实现与实测结果（第 161 轮）

**已实现**：`CHAITE_SIM_PHASE_HOLD_EDGE=1` 与 `CHAITE_SIM_PHASE_HOLD_EDGE_PX=<px>`
（`tools/GameProbe.cs` 的 `SimulatedPhaseTransitionHold`）。原来的停手只在"阈值处有危险射弹"时生效；
新增的这一半在**没有危险射弹**时也停手，直到 Boss 进入场地任一端 `px` 范围内才放开，目的就是让转阶段
与随之而来的龙卷发生在版边。

**实测结果：在低 DPS 下是彻底的 no-op，而且原因是结构性的。**

```
strong 600  停手关   : 4218 tick, 6 受击, boss 剩 41203
            版边 900 : 4218 tick, 6 受击, boss 剩 41203   <- 逐字节相同
            版边 1400: 4218 tick, 6 受击, boss 剩 41203   <- 逐字节相同
strong 300  版边 1400: 4218 tick, 6 受击, boss 剩 59588   <- 死亡 tick 也相同
```

**为什么无效果**：死亡发生在 `bossLife = 41203`，而 50% 阈值是 `78000 × 0.5 = 39000`。也就是说
**战斗在进入二阶段之前就结束了**——玩家在**唯一一次转阶段发生之前**就已经死了。控血规律控制的是
"转阶段发生在哪里"，而低 DPS 的失败点是**一阶段内部的冲刺**，那里根本还没有转阶段可控。

**这条纠正了我自己在本文件第 124 节的推理**：第 124 节说"哪些攻击循环出现是 DPS 的函数、玩家无法干预"，
这句话**对于一阶段内部的失败而言是对的**——控转阶段无法救一阶段。但业主给的规律依然成立，只是它作用的
区间是"能活到 50% 阈值之后的战斗"，因此它的价值在于**把已经能存活的战斗推得更稳**，
而不是拯救当前在 24% 就崩掉的低 DPS 配置。

## 9. 因此真正的低 DPS 瓶颈（修正后）

低 DPS 必须先解决**一阶段内部**的存活，才轮到转阶段控制。而坐实的数据指向两个一阶段问题：

1. **垂直逃逸分量缺失**（§127：需要约 -10 px/tick，实得约 0），而弹幕与业主都指出
   "本质就是上下跳"、"W 型走位"——即**垂直机动才是主要手段**。
2. **克盾时机**（§128：朝 BOSS 冲刺时 ttc=6/10 让 boss 剩 3641，是迄今最佳）。

这两条都在一阶段即可生效，不依赖转阶段。**下一步应集中在垂直逃逸分量上**，而不是转阶段控制。
