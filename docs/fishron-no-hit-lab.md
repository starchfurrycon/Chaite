# 猪鲨无伤：离线确定性实验台与测量结果

状态：**未达成无伤**。本文记录的是测量与否定结果，不是成功声明。

## 1. 为什么可以离线算

`docs/fishron-ai-spec.md` 从**已定版 1.4.5.8 程序集**的 IL 得出结论：`AI_069_DukeFishron`
里 `Main.rand` 只出现在 6 处尘土和 1 处阶段 2 环形泡泡的**尺寸**上，冲刺的间隔、方向、
次数与随机数无关。冲刺在进入状态的那一 tick 一次性把速度设为
`normalize(player.Center - Center) * num7`，此后是严格直线。

因此在一场战斗里，**Boss 的轨迹是玩家输入序列的函数**。只要玩家物理可信，整场战斗
就可以离线逐 tick 复现，不需要跑游戏客户端。

## 2. 实验台

新增 `tests/Chaite.Tests/FishronNoHitLab.cs`，通过显式开关
`--fishron-no-hit-lab` 运行（不进入默认测试集）：

- **玩家**：直接调用仓库已有的 `PlayerForwardModel.TryAdvance`。该模型是引擎实测标定
  的（跳跃 5.01/15、重力 0.4、WingMovement 常量、地面钳制顺序），不是新写的近似。
- **Boss**：按 `docs/fishron-ai-spec.md` 的专家数值转写 AI_069 的悬停／冲刺／泡泡／
  龙卷风／传送状态机。
- **威胁**：Detonating Bubble（NPC 371）、Sharknado / Cthulhunado（384/386）、
  Sharkron（372/373）。

实验台自带**反证**：被动站立探针在第 55 tick 被冲刺击中，说明它确实会判命中——
一个从不报命中的模拟器什么也证明不了。

## 3. 测量结果

### 3.1 冲刺所需的垂直净空

玩家 20x42，Boss 150x100。冲刺方向与水平夹角 theta 时，玩家中心相对冲刺直线所需的
**垂直距离**约为：

- theta = 34 度 → 约 80 px
- theta = 70 度 → 约 108 px

玩家最大水平速度 6.75 px/tick（靴子 + 翅膀），28 tick 内总位移上限约 189 px，
所以**只有当位移里有一半以上落在垂直方向时**才够。这意味着玩家必须在冲刺生效**之前**
就已经在移动，而从静止加速只有 0.08 px/tick^2，来不及。

### 3.2 爬升会把冲刺变陡（关键负面发现）

Boss 悬停目标点是 `player.Center + (ai[1], -200)`，其中 `ai[1] = ±300`，它用
8.5 px/tick 追踪该点。玩家爬升会让 Boss 跟着上升，于是冲刺角度从约 34 度变成约 70 度，
所需净空从 80 px 涨到 108 px。**爬升越多，冲刺越难躲。**

实测（20,000 tick，248 次冲刺，仅计本体接触）：

| 悬停策略 | 命中 tick 数 | 峰值垂直净空 |
|---|---:|---:|
| 全程爬升 lead=30 | 1378 | 203 px |
| 贴地不爬 lead=30 | 3164 | 104 px |
| 匀速横跑 | 1878 | 174 px |
| 匀速横跑 + 冲刺 | 1878 | 174 px |

净空**能**超过所需的 80-108 px（爬升策略到 203 px），但命中数仍然很高：净空是整段
冲刺里的峰值，而命中取决于**最近接近那一刻**的净空，两者不是同一个量。这是本轮最
重要的方法论教训——用峰值净空当指标会给出假阳性。

### 3.3 冲刺（Shield of Cthulhu）在实验台里无效

`PlayerControlFrame.Dash` 在实验台改不动结果：所有 dash 参数扫描给出完全相同的数字。
原因是 `PlayerForwardModel` 的冲刺子状态没有从帧外接入（`DashReady` 不在
`PlayerMotionFrame` 上），且 `ToSnapshot` 不携带它。**所以本实验台无法评估冲刺**——
这条限制必须在读上面任何 dash 相关数字时记住。

### 3.4 与仓库内既有失败测试的交叉印证

`dotnet` 全量测试里 4 个与残余策略冲刺相关的用例本来就失败：

```
FAIL PolicyKeepsTheBranchLabelItAdjusted
FAIL HeldDashIsNotSpentUntilItIsIssued
FAIL ForcedDashDoesNotBurnTheChargesDash
FAIL DashHeadSeparatesHoldingFromForcing
```

外加 2 个只因为缺少 `tests/Chaite.Tests/fixtures/observation-conformance.jsonl`
（需先跑生成脚本）而失败。这 6 个失败与本次改动无关（改动只在 Manager 的 UI 与测试
项目文件清单），但它们说明**残余策略的冲刺通路当前是坏的**，这与 3.3 的观察一致。

## 4. 结论

1. Boss 确实完全确定，无伤在原理上是一个可解的离线搜索问题——实验台已经能把整场
   战斗算出来。
2. 但**当前配装下的机动预算是紧的**：玩家 6.75 px/tick 对冲刺 17 px/tick，躲避必须
   靠"提前移动 + 垂直分量"，而唯一能大幅提高垂直/水平逃逸量的冲刺在本实验台里
   没有接通，无法验证。
3. 手写状态机失败的直接原因不是"没找到正确拍子"，而是**指标错了**：追逐峰值净空
   不能代替最近接近净空。下一步应改为对每次冲刺记录"最近接近时刻的净空"，并用
   真正的搜索（而不是参数扫描）在输入空间里找零命中序列。

## 5. 实验台边界（不得越界宣称）

- 玩家模型覆盖的是仓库已审查的干燥、正重力、普通/云跳 + 翅膀子集；坐骑、钩爪、
  液体、倒重力都会返回 `ForwardModelRefusal`，实验台会如实报告而不是猜。
- Boss 状态机是从 IL 规格**转写**的，不是从引擎热路径直接抄的。泡泡／龙卷风的
  生成位置与 Sharkron 弹道是近似（速度、生命周期取自规格，具体生成偏移未逐条核对）。
- 一次命中即计一次接触 tick，不是一次事件；表中数字是接触 tick 数。
- 以上任何数字都不构成对真实客户端的验收证据。真实验收仍须隔离原版探针逐种子实测。
