# 常用特殊远程武器原生机制审计（Terraria 1.4.5.8）

## 结论

这一批八件武器都能继续适配，但不能复用普通直线弹丸的通用模型。可以直接进入生产实现的边界如下：

| 武器 | 生产模型 | 可安全落地的前提 |
|---|---|---|
| 榴弹发射器 `758` | 15 次无重力更新后下坠的离散抛射 | 逐更新求交；地图会阻挡/反弹时读取碰撞或保守停火 |
| 火箭发射器 `759` | 分量阈值控制的指数加速直射 | 逐更新求交；自动拒绝会改图的弹药 |
| 感应雷发射器 `760` | 阻尼重力下的布雷/路径覆盖 | 作为放置武器评分，不能伪装成普通直射武器；跟踪已有 20 枚上限 |
| 雪人炮 `1946` | 延迟搜索、视线约束的追踪火箭 | 读取候选 NPC 与视线；目标集合不完整时使用保守包络 |
| 电圈发射器 `2796` | 在目标 tile 或首次碰撞处放置持续伤害区 | 单独的落点/覆盖控制器；不能按一发直线伤害计分 |
| 异星泡泡枪 `2797` | 约 0.5 秒后、按届时鼠标位置会聚的 4/5 发齐射 | 读取在途泡泡，并把实际弹种交给对应弹药求解器 |
| 星旋机枪 `3475` | 持枪弹幕每 5 更新发弹、七事件附送一枚追踪火箭 | 读取持枪弹幕 `615` 的实时相位；支持战中接管 |
| 喜庆弹射器 Mk2 `3930` | 持枪弹幕驱动的七状态火箭序列 | 读取持枪弹幕 `714` 的实时相位，并按七种状态逐一求解 |

这里的“可落地”是原版源码合同结论，不是已经完成真实 Boss 战验收。任何新模型在接入自动开火前仍应有离线状态机回归、原生逐发观测和真实战斗证据。

## 四种 `AI_016` 发射器

### 榴弹发射器

- 榴弹族的初始 `ai[0]=0`。每次更新末尾先令 `ai[0]++`；当它大于 15 时才施加 `velocity.Y += 0.2`，所以第 16 次 projectile update 是第一次下坠更新。
- 撞砖时受阻分量乘 `-0.4` 反弹；落地且 `velocity.Y==0` 时水平速度再乘 `0.95`。
- 基础 Rocket I–IV 榴弹以及对应的特殊榴弹由 `NewProjectile` 把寿命设为 180 更新，即约 3 秒，而非默认 3600。
- 它适合离散、分段二次轨迹求交。只看连续抛物线会在重力启用边界产生一帧误差。

### 火箭发射器

- 对直射火箭族，只要 `abs(vx)<15` 且 `abs(vy)<15`，每次更新就执行 `velocity *= 1.1`。任一分量达到阈值后不再加速。
- 没有重力；撞砖后速度清零、透明，并把寿命压到 3 以触发爆炸。
- 这是确定性的逐更新轨迹，可以快速迭代求交；不能把基础 `shootSpeed=5` 当成全程恒速。

### 感应雷发射器

- 每次更新顺序为 `velocity.Y += 0.2`，随后整个向量乘 `0.97`；因此无碰撞递推为 `v[n+1]=0.97*(v[n]+(0,0.2))`。
- 接近静止时分量会归零，雷继续以碰撞体等待 NPC 接触；它不是搜索附近敌人的追踪弹。
- 每次发射后，玩家会枚举自己的 12 种感应雷弹幕。总数超过 20 时直接 `Kill()` 最老的一枚，因此第 21 枚可能让远处旧雷立刻爆炸，也可能触发对应改图/液体效果。
- 生产评分应考虑 Boss 未来路径、地面和现有雷区，不应给它普通直射 DPS。

### 雪人炮

- 第 31 次 projectile update 开始，在 600 像素曼哈顿距离且有视线的可追踪 NPC 中选择最近目标。
- 锁定后只要目标仍可追踪且在 1000 像素曼哈顿距离内，就保留该目标；期望速度为 16，每更新执行 `velocity=Lerp(velocity,targetVelocity,1/12)`。
- 搜索顺序、其他 NPC 和视线会影响最终锁定对象。Boss 并非唯一候选时，只有完整读取候选集合才能称为精确模拟。

### 爆炸、集束与地图副作用

| 弹幕族 | 原生伤害矩形 | 额外行为 |
|---|---:|---|
| Rocket I/II | 128×128 | II 拆图半径 3 tile |
| Rocket III/IV | 200×200 | IV 拆图半径 5 tile |
| Cluster parent | 128×128 | 生成 6 枚半伤害子弹幕；II 还拆图半径 3 tile |
| Cluster child | 48×48 | 寿命 60 更新；不继承 parent 的拆图半径 |
| Mini Nuke I/II | 250×250 | II 拆图半径 7 tile；Snowman 809 见下方例外 |
| Wet/Lava/Honey/Dry | 48×48 | 分别生成水/岩浆/蜂蜜/移除液体，属于世界写操作 |
| Celebration 715/716 | 128×128 | 716 拆图半径 3 tile |
| Celebration 717/718 | 240×240 | 718 拆图半径 5 tile；没有 Cluster/液体的原副作用 |

`PrepareBombToBlow` 在这版原生 IL 中连续比较了两次 `projectile type 808`，却没有比较 `809`。因此 Snowman Cannon + Mini Nuke II 的死亡爆炸伤害矩形不会被放大到 250×250，仍是当时的 14×14；但 `Kill_ExplodeTiles` 又确实把 809 列入半径 7 tile 的拆图集合。这是白名单版本的真实不对称，适配器不能自行“修正”为对称行为。

默认安全策略应拒绝 Rocket II、Rocket IV、Cluster Rocket II、Mini Nuke II，以及普通四发射器上的 Wet/Lava/Honey/Dry。除非用户另行明确允许世界修改，否则不能仅因目标是 Boss 就自动发射。喜庆弹射器上的液体/Dry 弹会折叠成 717，不产生液体副作用；仍需按实际最终弹幕判断，而不是只看弹药名字。

## 异星泡泡枪 `2797`

一次使用只调用、只消耗一次 `PickAmmo`，随后生成：

- 4 枚泡泡，概率 75%；
- 5 枚泡泡，概率 25%；
- 所以保证输出是 4 枚真实子弹，期望值是 4.25，不能把第 5 枚计入保证 DPS。

若枪口前方 40×`item.scale` 像素有视线，出生点会先向前平移这段距离。每个泡泡独立取：

- 初始速度倍率 `r ∈ [0.05,0.25)`；
- 相对开枪方向 `φ ∈ [-60°,60°)`；
- 初速 `v0 = r * pickedAmmoSpeed * rotate(aimUnit,φ)`。

泡泡弹幕 `444` 有 `extraUpdates=1`，拥有 60 个 projectile update，名义寿命约 30 game tick。无碰撞时第 `k` 个子步：

`angle(v[k]) = originalAim + 0.95^k * φ`

`|v[k]| = pickedAmmoSpeed * r * 0.96^k`

`P[k] = P[k-1] + v[k]`

60 步后速度只剩初速的 `0.96^60 = 0.0863523`，最大角误差只剩约 `2.764°`。路径长度上界为 `pickedAmmoSpeed*r*0.96*(1-0.96^60)/0.04`；默认 Musket Ball 的实际选弹速度是 `12+4=16`，最大路径长度小于约 87.71 像素，另加最多 40×scale 的出生前移。

决定瞄准语义的关键事实是：

- `Damage_CanDealDamage` 对 444 无条件返回 false，泡泡本身不会伤害 Boss，也不会因碰 NPC 爆开。
- 碰砖时受阻分量完全反射，并把期望方向改成反射后方向；泡泡仍继续衰减。
- 泡泡死亡时，owner 客户端从泡泡当前位置朝“死亡这一刻的当前鼠标世界坐标”发射保存的真实弹种，速度为保存的 `PickAmmo` 结果。它不使用开枪时鼠标，也不沿泡泡当前速度发射。

所以接管可以在泡泡已经飞行时开始。运行时应读取 owner 的 444：`Center/timeLeft/ai[0]/localAI[0]/localAI[1]`。目标预测时域是“剩余爆泡时间 + 真实子弹飞行时间”，并由所有同批泡泡共享一个会聚鼠标点。真实弹种之后的重力、追踪、穿透或爆炸仍必须交给该弹药自己的求解器。

默认 Musket Ball 每枚释放弹的名义伤害为 `45+7=52`。这不是 4 枚合计值，也不是包含防御、暴击或随机第 5 枚的值。

## 电圈发射器 `2796`

### 旅行弹幕 442

- 一次正常 `PickAmmo` 后强制使用 442，并把开火时的 `tileTargetX/Y` 写进 `ai[0/1]`。之后移动鼠标不会改变在途弹幕。
- 442 以实际选弹速度恒速直线运动；无重力、无散射、无转向。
- 每次 AI 先检查中心到 `tileTarget*16+(8,8)` 是否不超过 16 像素；满足即引爆。撞砖也在碰撞处引爆。
- 442 与 NPC 相交时会在原生伤害结算之前直接 `Kill()` 并返回，因此旅行弹本身对 NPC/Boss 造成 **0 直接伤害**，只在接触点生成 443。
- 若没有更早事件，显形后计数达到 120 时在移动前死亡；总计约第 125 次更新，最后移动位置约为 `P0+124*v`。默认速度 12 时最大无障碍放置距离约 1488 像素。

目标 tile 是 16 像素量化点。精确无障碍求解应寻找最小 `n≤124`，使 `distance(P0+n*v,tileCenter)≤16`，并把 NPC/砖碰撞作为更早事件，而不是假定电圈总生成在鼠标的精确像素坐标。

### 持续区弹幕 443

- 在 442 的引爆中心生成，继承伤害但击退固定为 0；`NewProjectile` 把寿命设为 300 更新，即 5 秒。
- 没有 tile collision、忽略液体，不要求视线，可以隔砖按矩形重叠伤害。
- `ai[0]` 形成确定性的 30-tick 尺寸脉动。实际轴对齐正方形为 62×62 至 80×80；保证核心只能按 62×62（各轴约 ±31）计算，80×80 是瞬时包络。读取 `ai[0]` 后可逐 tick 精确。
- 对同一 NPC，每次成功命中写入 `targetNPC.immune[owner]=8`，所以持续重叠时最多约每 8 tick 一次、约 7.5 hit/s。这是同 owner 的共享免疫；堆多个电圈不能线性叠高单一 hitbox 的频率，但能扩大覆盖或分别命中多个实体/部件。
- 新的 442 引爆时，以新中心 ±40 构造 80×80 矩形。与其相交的同 owner 旧 443 会立刻失去伤害能力，并在 5 tick 内收拢、淡出、死亡；随后才生成新 443。反复瞄同一点会不断用新区域替换仍有寿命的旧区域。

因此它的评分目标是 Boss 在未来 5 秒内进入 62×62 保证核心的覆盖时间，而非“旅行弹单发命中率”。战中接管时，应读取在途 442 和已有 443；已发射的 442 不可再转向，后续射击才可重新选择落点。

## 星旋机枪 `3475`

第一次 `ItemCheck_Shoot` 只选择弹药以确认可用性；因为 `ItemID.Sets.gunProj[3475]`，这次选择不耗弹，且弹药的伤害/速度会被重置为武器值。真正的逐发选弹发生在持枪弹幕 615 内：

- 新建 615 时 `ai[0]=5*rand(0..19)`，所以开始相位随机；之后每 5 game update 发一次真实子弹。
- 每个事件重新 `PickAmmo`，真实子弹初速基数为 `14 + ammo.shootSpeed`，不是物品栏写出的 `20 + ammo.shootSpeed`。
- 持枪方向相对鼠标随机 ±3.75°，真实子弹再随机 ±5.625°；最坏合成角包络为 ±9.375°。
- 每第 7 个发弹事件额外生成一枚 616，不额外选弹或耗弹，伤害为同次真实子弹 `+20`，击退乘 `1.25`。
- 每次真实选弹固有 `2/3` 不消耗弹药；其他弹药节省效果仍在 `PickAmmo` 中继续叠加。

616 初速为每 projectile update 8，`extraUpdates=2`，总寿命 90 game tick。第 21 个 projectile update 起搜索 800 像素曼哈顿距离且有视线的 NPC，保留目标阈值为 1000；锁定后保持原速并以 `1/8` 平滑转向。其初始角相对持枪方向再随机 ±11.25°，对鼠标的最坏合成包络为 ±15°。死亡时造成 80×80 爆炸伤害且不拆图。

Musket Ball 下真实子弹名义伤害为 57，616 的弹幕伤害字段为 77。616 是 `penetrate=1` 的直击加死亡爆炸弹幕，源码路径允许直击与爆炸各走一次结算；在把双段伤害计入保证 DPS 前，仍应以原生逐发命中证据核对 Boss 共享免疫与命中顺序。

战中接管必须优先复用已经存在的 615，并读取其 `ai[0]/ai[1]`，而不是按物品 `useTime=20` 猜下一发时刻。若未捕获实时相位，最多只能在完整七事件窗口内使用“一枚附送火箭”的保守结论。

## 喜庆弹射器 Mk2 `3930`

它与星旋机枪同样先生成不耗弹的持枪弹幕 714，真正选弹发生在 714 中：

- 每 8 game update 一个 firing event；每个 event 只调用一次 `PickAmmo`。
- 七状态循环中，状态 4 发 2 枚，状态 5 发 3 枚，另外五个状态各 1 枚，所以完整七事件必有 10 枚火箭。
- 多枚火箭的 event 仍至多消耗一发弹药；每个 event 固有 `1/2` 不耗弹。
- 状态 3 的选弹初速基数为 9，其余为 8；物品 `shootSpeed=17` 只参与持枪方向，不是实际火箭初速。
- 持枪方向随机 ±1.875°，每枚火箭再随机 ±5.625°，对鼠标的最坏合成角包络为 ±7.5°。

最终弹幕 715–718 都有 `extraUpdates=2`，名义寿命 360 game tick。写入每枚火箭的 `ai[0]=state` 后执行不同轨迹：

| 状态 | 原生轨迹要点 |
|---:|---|
| 0 | 第 20 projectile update 后开始 `+0.12 Y`；改为无限穿透；每 20 更新播放一次爆炸视觉 |
| 1 | 第 10 更新先 `-10 Y`，随后每更新 `+0.25 Y`，逐渐放大 |
| 2 | 第 60 更新后每更新 `+0.15 Y` |
| 3 | 第 20 更新后以 800 曼哈顿距离+视线搜索；保留阈值 1000，以 `1/8` 平滑追踪；无目标时第 25 更新后 `+0.15 Y` |
| 4 | 沿垂直于速度的方向正弦摆动，第 10 更新后 `+0.04 Y`；同 event 第二枚相位相反 |
| 5 | 第 40 更新后每更新 `+0.08 Y`；同 event 形成三发小扇形 |
| 6 | 第 30 更新后每更新 `+0.1 Y` |

状态阈值单位是 projectile update；由于 `extraUpdates=2`，每个 game tick 通常有三次更新。所有状态的下落速度 `Y` 上限为 16。通用直线求交不仅会误判状态 1/4/5，也会忽略状态 0 的穿透与状态 3 的目标选择。

715–718 初始 `penetrate=1`，死亡时再按 128×128 或 240×240 矩形结算爆炸。与 616 相同，直击后存在第二次死亡爆炸结算路径；生产保证值应等原生逐发观测确认后再计入，而不是仅凭理论路径把伤害翻倍。

战中接管应扫描 owner 的 714，读取 `ai[0]/ai[1]` 并推导下一 event 和状态。已有 715–718 还应读取 `ai/localAI/velocity/timeLeft`，从当前状态继续轨迹，而不是强制重新进入状态 0。

## 生产接线要求

当前 `WeaponBallisticKind` 的普通直线、指数阻尼和离散竖直加速三类不足以表达这八件武器。后续实现至少应保持以下独立合同：

1. 发射器与弹药组合是显式白名单；运行时武器、弹药、最终弹幕、伤害和速度有一项不一致就停火。
2. 榴弹、加速火箭、阻尼感应雷、LOS 追踪、目标 tile 区域、延迟会聚齐射、持枪七事件和 Celebration 七状态不能互相降级为“看起来差不多”的直线解。
3. 中途接管时扫描并恢复 owner 的 442/443/444/615/616/714–718 与相关 `ai/localAI/timeLeft`。没有状态时等待新的安全 firing boundary，而不是猜相位。
4. 对 444 的真实弹种继续逐弹药适配；不认识的弹药、会改变飞行 AI 的外部饰品状态或无法确认的弹幕身份一律失败关闭。
5. 世界写风险按最终弹幕判断并默认禁止。感应雷上限触发的旧雷爆炸也属于这条安全边界。
6. 伤害评分读取实时前缀和玩家倍率。随机第 5 泡泡、Cluster 子弹、穿透、爆炸双段与追踪附加命中，在没有原生证据前不计入保证 DPS。
7. 持续区使用覆盖时间和共享免疫评分；召唤/魔法耗蓝、鞭子等其他输出路线继续走现有独立合同，不与本审计的火器模型混用。

常用武器覆盖仍未结束。Coin Gun、喷火器族、Phantasm、Eventide、特殊飞镖/Stake/Flare 等需要下一批逐件审计；Star Cannon 与 Super Star Cannon 已在弹道目录中以独立陨星合同接入，但本文件其余项目仍没有被冒充成已支持。
